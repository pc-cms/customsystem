# Casino Monthly Balance + Expenses by Category — исправления и новая логика

## 1. Найденная причина «200 млн в сейфе»

В `fin_wallet_tx` знак задаётся видом операции: расходы хранятся ПОЛОЖИТЕЛЬНОЙ суммой (`kind = 'expense'`), а страница Wallets применяет правило `expense → −amount`. Отчёт же складывает суммы как есть.

Факт по Arusha, Safe TZS: expense +107 013 903, income +84 454 399, transfer_in +19 000 000, transfer_out −4 000 000, adjustment −10 065 361, стартовый флот 25 000 000 → отчёт показывает ≈221 млн вместо реального остатка.

Исправление: единое правило знака (`expense`, `collection`, `transfer_out`, `manual_expense` → минус) плюс учёт только проведённых движений (`posted_at IS NOT NULL`). Правило выносится в общий модуль, чтобы Wallets и отчёт считали одинаково.

## 2. Формулы (по вашим ответам)

- Строка = один день, всё «в моменте», без накопления.
- **Office**: приход (+) увеличивает ожидаемые деньги, отправка (−) уменьшает. Сейчас знак обратный — исправляем.
- **Fin Result** = Casino Result + Diff + Tips + Fees − Expenses + Office net.
- **Balance (день)** = (Деньги на конец вчера + Casino Result + Diff + Tips + Fees + Office net − Expenses) − Деньги на конец сегодня. Стремится к нулю, логика как Variance в Wallets.
- **Money** = Cage Casino + Cage Manager + Bank TZS + Bank USD на конец дня.

## 3. Строка «Start»

Над первым числом месяца добавляется строка **Start** — состояние на конец прошлого месяца (30/31 число):

- заполняются только колонки, где есть деньги и переходящие величины: Cage Casino, Cage Manager, Bank TZS, Bank USD, Money, а также Diff и Tips;
- значения автоподставляются из последнего закрытого дня предыдущего месяца, ячейки редактируемые;
- хранятся в БД (per casino + месяц), а не в localStorage — плитка Starting Balance убирается, её роль берёт строка Start;
- первый день месяца считает Balance от строки Start.

## 4. Снимок на момент закрытия

Кошельки динамические, поэтому вчерашние строки «уплывают». Вводим снимок:

- при закрытии бизнес-дня (`close_business_day`) записывается снимок состояния денег этого дня: Cage (наличные/безнал/слоты), Cage Manager по кошелькам, Bank TZS/USD, Diff, Tips, Expenses, Office;
- отчёт для закрытых дней читает снимок, а не пересчитывает кошельки — цифры перестают меняться задним числом;
- кнопка **Record / Re-snapshot** в шапке отчёта (менеджер/финансы) перезаписывает снимок конкретного дня, если данные правились после закрытия;
- дни без снимка (исторические) считаются как сейчас, помечаются как расчётные.

## 5. Casino Monthly Balance — интерфейс

- Клик по строке больше не открывает общую панель (дублирует таблицу) — убираем.
- Панель справа = разбивка ИМЕННО этой колонки, у каждой числовой колонки своя:
  - Diff → в шапке итог дня, ниже блоки Miss Chips (по номиналам) и Slots (карты игроков);
  - Casino Result → Live Game / Slots / Bar; Live Game → по столам;
  - Cage Casino → наличные по номиналам, безнал по провайдерам, слотовая касса;
  - Cage Manager → кошельки офиса; Bank → счета; Office → список движений; Expenses → расходы дня по категориям с описанием; Tips / Fees → список записей.
- Заголовок панели: название колонки · дата · итог (вмещается в одну строку).
- Убираем моргание колонки при наведении (ring/подсветку по hover).
- Разные заливки: sticky-колонки Date/Fin Result — свой плотный фон; шапка — свой; пересечение шапка×sticky — самый контрастный.
- Итоговая строка и KPI-плитки — жирный шрифт, полные суммы.

## 6. Expenses by Category

- В шапке остаётся только название месяца и стрелки; поле выбора месяца (`type="month"`) убирается.
- Колонка Category получает отдельную заливку и двойную правую границу, чтобы не сливалась с днями.
- Клик по итогу дня в нижней строке Total открывает панель со ВСЕМИ расходами этого дня (все категории, с описанием и кошельком), в шапке — итог дня.
- Клик по общему Total месяца — все расходы месяца списком.
