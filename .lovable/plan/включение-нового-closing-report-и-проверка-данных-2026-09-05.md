# Включение нового Closing Report и проверка данных

## Что будет сделано

### 1. Включить новый макет во всех четырёх филиалах
Arusha, Dodoma, Mbeya, Mwanza переключаются на новый макет печати (сейчас у всех стоит старый). Ставка налога на выигрыши остаётся 15%. Переключатель в настройках филиала сохраняется — старый макет можно вернуть в любой момент.

Затрагиваются обе кассы: слоты (4 страницы: слоты, живая игра, движение фишек, итоговая) и живая игра (закрытие смены + движение фишек).

### 2. Тест печати на тестовых данных
На тестовой смене слотов и тестовой смене живой игры за свежую рабочую дату:
- заполняются Taxable Winnings Paid, Jackpot Count, Adjustment / Incident Ref;
- смена закрывается и открывается печать;
- со страниц снимаются скриншоты, и я сверяю: значения полей попали в блок Closing Record, налог на выигрыши посчитан от введённой суммы по ставке филиала, ссылка на инцидент выведена текстом, а не пропущена;
- проверяется, что введённые значения действительно сохранились в базе (сейчас по всем сменам они пустые — то есть ни одного реального ввода ещё не было).

Тесты выполняются на существующих сменах в тестовом окружении, реальные закрытые смены не редактируются.

### 3. Сводка соответствия кошельков и отчёта
Готовлю таблицу «кошелёк филиала → строка отчёта» по всем четырём филиалам и список того, что в кассовый отчёт не попадает, с указанием причины (офисный кошелёк / нет ввода в кассе).

Предварительно из справочника видно:
- Наличные TZS, USD, EUR, GBP, KES — попадают в Cash Flow.
- CRDB TZS/USD, NBC TZS/USD, Selcom TZS/USD — попадают в блок Bank Accounts.
- M-Pesa, Tigo Pesa, HaloPesa, Airtel Money, Main Phone — попадают в блок Cashless.
- I&M TZS и I&M USD — в кассе не заполняются и в отчёт не попадают (по вашему решению оставляем как есть, будет отмечено в сводке как сознательное исключение).
- WeChat, Selcom Float, Safe Live, Safe Slots — офисные кошельки, в кассовый отчёт не входят.

Итоговый список неучтённых кошельков выдам в чат после фактической проверки данных, а не только по справочнику.

## Технические детали
- `casinos.report_layout` = `'v2'` для всех четырёх филиалов (изменение данных, через миграцию/скрипт обновления).
- Проверка печати — Playwright на локальном превью, скриншоты страниц отчёта.
- Сверка кошельков: `fin_wallets` по каждому филиалу против `BANK_CHANNELS` / `MOBILE_PROVIDERS` в `src/components/cage/CageHelpers.ts` и динамических строк в `SlotsClosingReportV2` / `LiveClosingReportV2` (доп. ключи из данных смены).
- Код отчётов не меняется; правки только настроечные, плюс исправления, если тест печати выявит ошибку в выводе новых полей.
