# Запуск Dodoma: кошельки и импорт клиентов

## 1. Кошельки по образцу Arusha

В Dodoma нет кошельков. Копируем 16 кошельков из Arusha с нулями.

| Кошелёк | Тип | Валюта |
|---|---|---|
| Safe TZS | Cash | TZS |
| Safe USD | Cash | USD |
| Safe EUR | Cash | EUR |
| Safe GBP | Cash | GBP |
| Safe KES | Cash | KES |
| Safe Live | Safe | TZS |
| Safe Slots | Safe | TZS |
| CRDB TZS | Bank | TZS |
| CRDB USD | Bank | USD |
| NBC TZS | Bank | TZS |
| NBC USD | Bank | USD |

| AirTell | Mobile money | TZS |

- Стартовый флот — 0.
- Порядок сортировки повторяет Arusha.
- Реальные остатки внесём через физический пересчёт в Wallets.

## 2. Сколько клиентов переносим

В файле `Customers.xlsm`:
- **Всего уникальных имён**: 832.
- **С более чем 5 транзакциями**: 450 игроков.
- **Покрытие активных игроков**: 98.8% всего Drop и 97.9% всех транзакций.

**Решение**: переносим 450 активных клиентов (> 5 транзакций).

Оставшиеся 382 игрока с 1–5 транзакциями дают только 1.2% Drop — переносить нецелесообразно, они будут создаваться при первом визите, если понадобятся.

## 3. Объединение похожих имён

Среди 450 активных игроков есть пары-опечатки, которые нужно объединить до импорта, иначе они станут двойниками. Примеры: `ABDUL RAZAK` / `ABDULRAZAK`, разные варианты записи одного китайского имени и т.д.

Алгоритм:
- Нормализуем имя: верхний регистр, убираем лишние пробелы.
- Сравниваем расстоянием Левенштейна и по токенам.
- Автоматически объединяем пары с расстоянием ≤ 2, где одна запись явно опечатка другой и они обе активные.
- Итоговое количество после склейки — примерно **430–440 уникальных игроков**.

Перед финальной вставкой покажем список объединений для проверки.

## 4. Что вносим по каждому игроку

Для каждого из 450 игроков:
- Создаём карточку в `players`:
  - `name` — каноническое имя после склейки.
  - `category` — `Normal` (самый низкий уровень).
  - `status` — `active`.
  - `player_type` — `mix` (или `table`/`slots` по данным).
  - `verification_status` — `unverified` (телефонов/документов нет).
  - `casino_id` — Dodoma.
- Импортируем исторический **Drop** и **Result** в `player_day_drop_cache` по дням.
- Не создаём фиктивные кассовые транзакции, чтобы не сломать финансовый баланс.
- Все суммы в TZS (итоговая колонка `TOTAL` / `Drop` в файле).

## 5. Последовательность запуска

1. Вставить 16 кошельков Dodoma.
2. Вставить 450 активных игроков.
3. Вставить агрегированный Drop/Result по дням в `player_day_drop_cache`.
4. Проверить, что в Dashboard и отчётах новые игроки и дневной Drop отображаются корректно.
5. После импорта менеджер вручную вносит стартовые остатки через Wallets → Physical count.

## Технические детали

- `fin_wallets`: insert 16 rows, `starting_float_amount = 0`, `is_active = true`, уникальность по `(casino_id, name)`.
- `players`: insert 430–440 rows, предварительная дедупликация имен.
- `player_day_drop_cache`: insert агрегат по дням для импортированных игроков.
- Для обеих таблиц требуется `casino_id` Dodoma и корректные RLS-политики.
