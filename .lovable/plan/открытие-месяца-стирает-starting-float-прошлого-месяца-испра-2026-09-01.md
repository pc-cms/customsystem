# Открытие месяца стирает Starting Float прошлого месяца — исправление

## В чём проблема (проверено по данным)

Стартовый флот хранится одним «текущим» значением на кошелёк (`fin_wallets.starting_float_amount` + `starting_float_date`). Истории по месяцам нет.

Когда в Мбее открыли сентябрь, `fin_open_month` перезаписал все 20 кошельков:

| Кошелёк | Сейчас | Дата флота |
|---|---|---|
| Main Phone | 25 000 533 TZS | 01/09/2026 |
| Остальные 19 кошельков | 0 | 01/09/2026 |

При этом расчёт баланса (`fin_balance_snapshot`) берёт Starting Float прямо из `fin_wallets` **без фильтра по периоду**. Поэтому август теперь считается с сентябрьским флотом:

- собственный августовский флот обнулён на всех кошельках;
- весь сентябрьский флот сидит на одном кошельке (Main Phone) и добавляется и в Expected августа;
- Expected за август сдвинулся, Actual (физические счёты августа) — нет → отсюда минус.

Аруша (флот 01/08, 25 000 000) и Мванза (флот 01/08, 4 190 744) пока целы, но получат ровно ту же поломку, как только там откроют сентябрь. У Додомы флот не задан вовсе.

## Что делаем

### 1. Флот привязан к месяцу (главное)

Новая таблица `fin_wallet_float_history`: казино, кошелёк, `effective_date` = 1-е число открываемого месяца, сумма, валюта. `fin_open_month` пишет строки истории, а `fin_balance_snapshot` берёт по каждому кошельку последнюю строку с `effective_date <= начало выбранного месяца`. Открытие нового месяца больше физически не может изменить Expected/Variance прошлого.

### 2. Флот вводится одной суммой, разбивка подставляется сама

В Open Month Wizard:

- **Основное поле — Total Starting Float (TZS), одна сумма.** Её достаточно, чтобы открыть месяц.
- Ниже — авто-подстановка остатков по кошелькам из **последних физических счётов предыдущего месяца** (`cash_count_snapshots`, по одному последнему count на кошелёк). То есть вручную ничего вбивать не надо: система показывает «с чего мы реально начинаем» и сама складывает Total.
- Total можно поправить руками (тогда разница ложится на основной Cash-кошелёк), либо поправить отдельный кошелёк — Total пересчитается.
- Валютные кошельки (USD/EUR/GBP/KES) остаются в своей валюте, в Total идут по курсу дня из `fin_daily_rates`.

Так что вопрос «сумма или по кошелькам» решается обоими способами сразу: работаешь с суммой, разбивка есть под капотом и берётся из прошлого месяца автоматически.

### 3. Перенос сентябрьского флота Мбеи с Main Phone на фактические кошельки

Вместо одной суммы на Main Phone флот на 01/09/2026 раскладывается по реальным остаткам кошельков, а Cash TZS уменьшается так, чтобы Total вышел ровно 25 000 553 TZS:

| Кошелёк | Сумма |
|---|---|
| Cash TZS | 21 953 000 (было 24 418 000, −2 465 000) |
| Safe Live | 1 000 000 |
| Safe Slots | 1 000 000 |
| HaloPesa | 578 000 |
| Airtel Money | 285 910 |
| M-Pesa | 95 643 |
| Tigo Pesa | 88 000 |
| Cash USD | 40 USD |
| Main Phone | 0 |

Итого по TZS ровно **25 000 553** плюс 40 USD — это реальное состояние кошельков на открытие сентября.


### 4. Бэкфилл истории и восстановление августа

- История заполняется из текущих данных: Аруша 01/08, Мванза 01/08, Мбея 01/09 (уже по кошелькам из п.3).
- Августовский флот Мбеи восстанавливается строкой на 01/08/2026 — см. вопрос ниже.

## Что не трогаем

Day Closings, кассовые смены, расходы, доходы, JP, инter-casino переводы, физические счёты — не меняются. Меняется только хранение и чтение Starting Float по учётному месяцу и форма открытия месяца.

## Открытый вопрос

Августовский флот Мбеи затёрт и не восстанавливается из аудита (записей по `fin_wallets` в `fin_audit_log` нет). Назовите, пожалуйста, Total Starting Float Мбеи за август 2026 (одной суммой достаточно). Иначе август восстановится с нулевым флотом.

## Технические детали

- Миграция: `fin_wallet_float_history` (unique по wallet_id + effective_date) с GRANT (SELECT/INSERT authenticated, ALL service_role) и RLS по `has_casino_scope` / `can_finance` / `super_admin`.
- `fin_open_month`: upsert строк истории по `p_float_details`; `opening_float_tzs` считается по переданному набору, а не по текущим `fin_wallets`.
- `fin_balance_snapshot`: блок starting float → `DISTINCT ON (wallet_id)` по истории с `effective_date <= p_period_start`, `LEFT JOIN fin_wallets` за именем/валютой, fallback на `fin_wallets.starting_float_amount`.
- `OpenMonthWizard.tsx` + `use-fin-month-opening.ts`: Total-поле, авто-подстановка из последних `cash_count_snapshots` предыдущего месяца, двусторонний пересчёт Total ↔ кошельки, конвертация валют по `fin_daily_rates`.
- Правка данных: строки истории Аруша/Мванза (01/08), Мбея (01/09 по кошелькам) и восстановительная строка Мбея 01/08.
