# Blacklist: показываются 2 из 43 — отчёт и исправление

## Что случилось (проверено запросами к базе)

Никто никого из блэк-листа не удалял. Данные целы:

- Всего игроков: 1993
- Со статусом `blacklist`: **43** (все привязаны к казино Arusha; в других казино записей блэк-листа нет вообще)
- Последняя правка статусов — 27.07.2026, массовых снятий нет

Причина отображения только двух человек: страница Blacklist загружает **всех** игроков одним запросом
`from("players").select("*").order("updated_at desc")` без постраничной выборки. Сервер API отдаёт максимум
1000 строк за запрос. В первые 1000 самых свежих по `updated_at` игроков попадает ровно **2** записи блэк-листа —
остальные 41 обрезаются на границе лимита. Проверено запросом: `bl_in_first_1000 = 2`, `total_bl = 43`.

То есть это чисто ошибка выборки на клиенте, база в порядке.

## Что чиню

1. Страница Blacklist запрашивает только заблокированных игроков: фильтр `status = 'blacklist'` на сервере,
   а не фильтрация массива после загрузки. 43 строки помещаются в один ответ, обрезки больше нет.
2. На всякий случай запрос идёт через `fetchPaged` (уже используется в проекте), чтобы список не ломался,
   если блэк-лист вырастет больше 1000 человек.
3. Отдельный ключ кэша (`players-blacklist`) вместо общего `players`, чтобы не конфликтовать с другими экранами
   и не тянуть весь список игроков ради этой страницы — заодно страница станет заметно быстрее.
4. Офлайн-кэш блэк-листа (`blacklist-cache.ts`) будет наполняться из полного списка — сейчас туда попадали те же
   обрезанные 2 записи.
5. Поднять версию приложения.
