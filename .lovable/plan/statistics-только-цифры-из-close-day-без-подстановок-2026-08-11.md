# Statistics: только цифры из Close Day, без подстановок

## Правило

Колонки, которые вводятся в Close Day, показывают ровно то, что там введено. Никаких расчётных подстановок из смены. Если закрытия дня нет — показываем 0 и даём внести цифру вручную прямо в таблице. Если цифра пришла из Close Day — она только для чтения.

## Что меняется

### Statistics → Total, колонка Result Slots
- Источник: Net Win из Close Day (`fin_day_closing.net_win`) за бизнес-день.
- Fallback на системный `slots_result` убираем полностью.
- Нет закрытия дня → 0 (`·`), ячейка редактируемая инлайн (как Drop Slots): запись создаёт/обновляет цифру дня.
- Есть закрытие дня → значение read-only, при наведении подсказка «From Close Day».

### Statistics → Slots, колонка Cashdesk
- Источник: `fin_day_closing.cashdesk_win`.
- Fallback на `cash_desk_result` / `actual_cage_result` смены убираем.
- Нет закрытия дня → 0 (`·`), инлайн-ввод доступен менеджерам/финансам.
- Есть закрытие дня → read-only.

### Statistics → Slots, колонка Net Win
- Тот же принцип: значение из закрытия дня; при отсутствии закрытия — 0 с возможностью инлайн-ввода. Read-only, когда день закрыт.

Старые дни без закрытия покажут нули — это ожидаемо, их можно дозаполнить вручную из таблицы.

## Технические детали

- В `SlotsHistoryReport.tsx` запрос по `fin_day_closing` расширяем на `net_win`, `cashdesk_win`; `rows` строим строго из карты по `business_date`, без `??` фолбэков.
- В `Reports.tsx` (`TotalReport`) добавляем загрузку `fin_day_closing` (business_date, net_win) за период; `r.slotsResult` берём из неё, `manual_slots_result` и `slots_result` в этой колонке больше не используются.
- Инлайн-сохранение пишет в `fin_day_closing` через upsert по (`casino_id`, `business_date`) с обновлением только нужного поля; при создании строки остальные числовые поля остаются на дефолте 0. Права на редактирование: super_admin / manager / shift_manager / finance_manager.
- Редактируемость: ячейка редактируема только когда строки закрытия дня для этой даты нет. Как только закрытие появилось — блокируем.
- После сохранения инвалидируем `reports-total`, `slots-report-day-closings`, `cage-slots-history`.
- Поднимаем версию приложения в `package.json`.
