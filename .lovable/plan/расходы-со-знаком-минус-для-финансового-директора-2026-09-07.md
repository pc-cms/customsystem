# Расходы со знаком минус для финансового директора

## Что меняется

Финансовый директор (роль Finance Manager, а также Super Admin) сможет вносить расход с отрицательной суммой в любой категории — например, чтобы вернуть/сторнировать часть уже проведённого расхода без создания отдельной «обратной» записи.

Правила:
- Минус доступен только в разделе Office → Expenses (офисные расходы). Кассовые (сменные) расходы остаются только положительными.
- Ноль по-прежнему запрещён.
- Всем остальным ролям минус недоступен — поле не даст ввести знак, а база отклонит попытку.
- Отрицательная запись работает как обычный расход: пересчёт в шиллинги по курсу дня, влияние на кошелёк (возврат денег в кошелёк), Monthly Report, месячные закрытия и журнал изменений.
- Закрытые месяцы по-прежнему защищены: в них ничего внести нельзя.

## Где это видно

- Office → Expenses, форма добавления: сумма принимает минус (только для финансового директора).
- Диалог редактирования расхода: то же правило.
- В списке отрицательные суммы показываются в стиле отрицательных значений.
- Проверка превышения бюджета по категории при отрицательной сумме не срабатывает.

## Технические детали

База (миграция):
- `expenses`: заменить CHECK `amount > 0` на `amount <> 0`.
- `validate_expense()`: вместо `amount <= 0` — запрет только `amount = 0`; отрицательная сумма допускается лишь при `source = 'office'` и наличии у автора роли `finance_manager` или `super_admin` (через `has_role`), иначе исключение.
- Проверить `expenses_office_after_insert/after_approve/after_delete` и `expense_set_amount_tzs`: они должны корректно проводить сумму со знаком в `fin_wallet_tx` (сумма умножается на курс, знак сохраняется) — при необходимости убрать `abs()`/жёсткие направления.

Фронтенд:
- `FinancesExpensesPage.tsx`: `allowNegative` на `NumberInput` при наличии роли; условие `disabled` заменить с `!form.amount` на `form.amount === 0`; `overrunCheck` пропускать при отрицательной сумме; сумма из купюр (`cashSum`) остаётся положительной, минус вводится только вручную.
- `EditExpenseDialog.tsx`: та же логика для роли и валидации `Number(amount) !== 0`.
- Поднять версию сборки.

## Проверка

- Финансовый директор вносит −100 000 TZS в произвольной категории: запись создаётся, кошелёк растёт на эту сумму, Monthly Report уменьшает расходы категории.
- Пользователь без роли финансового директора не может ввести минус ни в форме, ни напрямую.
- Ноль отклоняется; закрытый месяц отклоняется.
