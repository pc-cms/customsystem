# Mbeya не попала в Boss Monthly Report — причина и исправление

## Что случилось (проверено по базе)

Замочек в Day Closings тут ни при чём — отчёт его вообще не проверяет. Отчёт берёт только те дни, по которым в закрытиях дня **есть строка с цифрами**.

- День 20/09 был закрыт в 07:00 во всех четырёх казино (запись о закрытии есть у всех).
- Но строка с цифрами дня создаётся автоматически только там, где к 07:00 пришли данные ACE. В то утро ACE прислал данные по Arusha, Dodoma, Mwanza — по Mbeya нет (ACE в Mbeya регулярно отстаёт на сутки).
- Поэтому у Mbeya за 20/09 строки не было вовсе, и её результат столов (13 765 000) в отчёт не попал.
- Строка появилась только сегодня в 07:43, когда менеджер вручную сохранил и закрыл день — после этого цифры в отчёте появились.

То есть проблема не в замке, а в том, что при закрытии дня строка дня создаётся не всегда.

## Что делаем

1. **Закрытие дня всегда создаёт строку дня.** При закрытии бизнес-дня (ручном и автоматическом в 07:00) для каждого казино создаётся строка закрытия дня, даже если данных ACE нет:
   - результат столов подставляется автоматически из закрытых смен столов за этот день;
   - слотовые поля остаются пустыми (0) и позже спокойно перезаписываются данными ACE или ручным вводом;
   - существующие строки не перетираются — только создаются недостающие.
2. **Отчёт не зависит от замка** — это уже так; дополнительно фиксируем это комментарием, чтобы правило не потерялось.
3. **Разовая доподготовка сентября**: создать недостающие строки дней за текущий месяц по всем казино тем же правилом (результат столов из смен), чтобы отчёт сразу был полным.

## Технические детали

- Функция `close_business_day` дополняется вставкой в `fin_day_closing` (`ON CONFLICT DO NOTHING`) с `tables_result = Σ shifts.tables_result` за закрываемую бизнес-дату; `locked_at` не ставится, чтобы менеджер по-прежнему подтверждал цифры.
- `force_close_business_day_0800` (крон 07:00) наследует поведение через `close_business_day`, отдельных правок расписания нет.
- `ace_seed_provisional_day_closing` не трогаем — он продолжает досыпать слотовые цифры, когда ACE приходит позже.
- RPC `boss_monthly_report` не меняется: она уже считает дни по `business_day_closures` + `fin_day_closing`, без `locked_at`.
- Разовый backfill: `INSERT ... SELECT` по дням с закрытием, но без строки в `fin_day_closing`, за 2026-09-01..сегодня.

## Что не трогаем

Коллектор ACE, финансовые пути, расписания кронов (кроме логики внутри закрытия дня), интерфейс Day Closings, формулы метрик. Публикация — только по вашему запросу.
