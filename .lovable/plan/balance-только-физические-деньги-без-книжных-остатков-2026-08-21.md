# Balance: только физические деньги, без «книжных» остатков

## Что сейчас
На экране Wallets / Balance живут два разных представления денег:

1. **Actual** — последний физический пересчёт кошелька. Это ваши реальные деньги.
2. **Ledger (book)** — сумма движений по кошельку из журнала транзакций. Она приходит из RPC `fin_balance_snapshot` (поля `ledger`, `ledger_native`, `ledger_tzs`) и используется как запасное значение, если пересчёта ещё не было. Плюс есть подсказка «expected denominations» — последний пересчёт ± номиналы движений после него.

Именно сравнение Actual с этим ledger я и называл «разрывами по кошелькам» (M-PESA / Safe / NBC). Это техническая сверка журнала, к вашей рабочей логике она отношения не имеет и только путает.

## Что делаем

### 1. Убрать «книжный» остаток из интерфейса полностью
- В Wallets убрать все отображения и fallback на `ledger* `: если физического пересчёта нет — показывать пустое значение (`·`), а не число из журнала.
- Убрать подсказку «expected denominations» (пересчёт ± движения) и связанный запрос к `fin_wallet_tx` — она строится по транзакциям.
- Итог по кошелькам (Grand Total TZS / по валютам) считать строго по последним пересчётам.

### 2. Balance оставить как контроль «приход − расход − остаток = 0»
Формула не меняется:

```text
Expected = Starting Float
         + Live Game + Slots + Other + JP
         + Card Balance + Miss Chips + Miss Cards
         − Expenses − Collections − Transfers

Actual   = Σ физических пересчётов кошельков

Variance = Actual − Expected      (должно быть 0)
```

Строка Variance остаётся на экране без переименования. Никаких других «разрывов» в системе больше не показывается.

### 3. Что это меняет на практике
- Кошелёк без пересчёта перестаёт «подставлять» цифру из журнала — сразу видно, что его надо пересчитать.
- Единственный показатель сходимости — Variance. Если он не 0, значит либо не пересчитали кошелёк, либо расход/приход не внесён.
