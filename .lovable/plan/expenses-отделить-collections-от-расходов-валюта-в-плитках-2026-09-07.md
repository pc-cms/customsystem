# Expenses: отделить Collections от расходов + валюта в плитках

## Что не сходится

Додома, август:

- Месячный отчёт «Total Expenses»: **175 480 829**
- Страница Expenses: **285 547 529**

Разница ровно **110 066 700** — это 5 записей, у которых категория помечена типом **Collection** (в месячном отчёте они идут отдельной группой и не считаются расходом). Страница Expenses складывает всё подряд: расходы, коллекции, CAPEX и переводы в одну сумму. Ошибки в данных нет — расходятся только правила подсчёта.

Проверено запросом: за август по Додоме в базе только два типа — `expense` 175 480 828.76 и `collection` 110 066 700.00.

## Что изменится на странице Expenses

Строки остаются в списке как есть — меняются только итоги.

### 1. Плитка Total → только настоящие расходы

```text
TOTAL EXPENSES
175 480 829 TZS
TZS 121 168 441 · USD 20 889
```

Рядом (только если такие записи есть в выборке) появляются подытоги:

```text
COLLECTIONS  110 066 700     CAPEX  0     TRANSFERS  0
```

### 2. Валюта во всех плитках

Под каждой суммой (Total, Approved, Live/Slots/Office) — мелкая вторая строка с разбивкой по валютам, как уже сделано в нижнем итоге таблицы: `TZS 231 235 141 · USD 20 889`. Строка показывается только если валют больше одной.

### 3. Нижний итог таблицы

Итог таблицы делится так же: главная сумма — расходы, ниже отдельными подытогами Collections / CAPEX / Transfers, чтобы общая сумма всех строк по-прежнему сходилась.

После этого «Total Expenses» на странице Expenses и в месячном отчёте показывают одно и то же число для любого филиала и месяца.

## Технические детали

- `src/hooks/use-expenses-analytics.ts` — добавить в результат разбивку по `bucket` (`expense` / `collection` / `capex` / `transfer`) и по валютам (`byCurrency`, `tzsTotal`) для каждой группы и для `bySource`. Bucket берётся из `fin_categories.bucket` по `fin_category_id` (карта категорий уже загружается на странице через `useFinCategories`); записи без категории считаются `expense`, как в SQL.
- Суммирование в TZS — по `amount_tzs ?? amount`, нативные суммы — по `amount` + `currency`; та же логика, что уже в футере таблицы.
- `src/pages/Expenses.tsx` — плитки (строки ~693-732), by-source плитки (~735-752), футер `SmartTable` (~921-941): подставить новые поля, вынести маленький компонент для второй строки с валютами.
- Серверная логика, `fin_balance_snapshot` и месячный отчёт не трогаем — исправление презентационное.
- Поднять версию в `package.json`.
