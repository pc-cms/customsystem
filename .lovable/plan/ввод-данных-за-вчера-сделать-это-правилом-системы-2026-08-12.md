# Ввод данных за вчера — сделать это правилом системы

Да, вносить данные за 11-е число 12-го — это нормальный и единственно правильный порядок: бизнес-день закрывается на следующий день. Проблема в том, что система этого пока не знает явно.

## Что сейчас не так

- У физических пересчётов кошельков (`cash_count_snapshots`) нет поля бизнес-даты. Сохраняется только момент времени.
- Отчёт угадывает дату по эвристике: если сегодняшний бизнес-день ещё не закрыт, а вчерашний закрыт — пересчёт «переносится» на вчера, иначе остаётся на сегодня. Из-за этого один и тот же пересчёт может попасть не в тот день, и Variance «прыгает».
- Экран Wallets показывает предупреждение о «устаревших пересчётах», хотя ситуация штатная.

## Что делаем

1. **Явная бизнес-дата у пересчёта.** Добавляем поле бизнес-даты в записи физического пересчёта кошельков. По умолчанию — день, который сейчас закрываем (вчерашний бизнес-день, пока он не закрыт; после закрытия — текущий).
2. **Селектор даты в Wallets.** Над таблицей — «Counting for: 11/08/2026» с возможностью выбрать день. Все пересчёты, сделанные в этой сессии, пишутся на выбранную дату. Кнопка Record использует ту же дату.
3. **Отчёты читают дату из записи.** Casino Monthly Balance / Daily Balance берут `business_date` пересчёта напрямую, эвристика убирается. Money за 11-е = последний пересчёт, помеченный 11-м, независимо от того, когда его физически сделали.
4. **Предупреждение о «stale counts» переписываем.** Оно срабатывает только если за закрываемый день пересчёта нет вообще, а не когда пересчёт сделан «на следующий день».
5. **То же правило для расходов и офисных движений** уже работает по бизнес-дате — проверим, что дата по умолчанию в формах ввода тоже равна закрываемому дню, а не календарному сегодня.

## Технические детали

- Миграция: `alter table cash_count_snapshots add column business_date date`; бэкофилл существующих строк через `business_date_of(created_at)` с поправкой по той же логике, что применяет отчёт сейчас, чтобы исторические цифры не поехали; далее `not null default` через триггер.
- `src/hooks/use-daily-balance-report.ts`: убрать `moneyDateOf`, использовать `c.business_date`.
- `src/pages/finances/FinancesWalletsPage.tsx`: селектор даты, передача даты в сохранение пересчёта, синхронизация с `dayToRecord()`.
- `src/components/office/StaleCountsNotice.tsx`: новый критерий срабатывания.
