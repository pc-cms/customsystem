# Company Report — оптимизация и прозрачность

Цель: сделать месячный отчёт Dashboard TV быстрым, корректным и понятным — чтобы по каждой цифре было видно, откуда она берётся.

## 1. Result — только закрытые дни

Сейчас в Result попадают незакрытые дни двумя путями: через fallback по открытым сменам/фишкам и через строку Day Closings за текущий день. Проверено: за 20.08 в `fin_day_closing` уже есть строка с нулями и пустым `closed_by`, созданная в 07:15 и обновлявшаяся в течение дня — она участвует в расчёте и «дёргает» баланс.

Что делаем:
- День попадает в отчёт, только если он реально закрыт: есть запись в `business_day_closures` (либо `closed_by IS NOT NULL` в `fin_day_closing`).
- Формула для закрытого дня — полная, без изменений: `tables_result (Live) + slots_result (Slots) − Players Card Balance`.
- Fallback по открытым сменам, `cage_slots_shifts` и снимкам фишек полностью убирается — открытый бизнес-день в отчёте отсутствует.
- В дневной таблице незакрытые дни показываются пустыми (`·`), а не нулём.
- В самом Day Closings строка за открытый бизнес-день больше не создаётся автоматически: поля показываются как placeholder (превью), запись в `fin_day_closing` появляется только при ручном сохранении или при закрытии дня. Существующая пустая строка за сегодня удаляется миграцией.


## 2. Производительность: один серверный расчёт вместо 8+N запросов

Сейчас отчёт делает 8 параллельных запросов к базе плюс отдельный вызов на каждый открытый день/казино (снимки фишек), и повторяет всё каждые 30 секунд.

Что делаем:
- Создаём одну серверную функцию `boss_monthly_report(_casino_ids, _year, _month)`, которая целиком считает месяц (Result, Other, Collection, Estimated, Extras, дневную разбивку) и возвращает готовый JSON.
- Клиентский хук вызывает только её; вся агрегация уходит с браузера на сервер.
- Отказ от live-fallback сам по себе убирает N дополнительных вызовов и два запроса к сменам.
- Интервал автообновления — 60 секунд, плюс мгновенное обновление после ручного редактирования Extra Expenses.

## 3. Корректность прогноза

`daysElapsed` сейчас считает только дни с ненулевым результатом, поэтому прогноз завышается.

Новая логика:
- `daysElapsed` = число закрытых бизнес-дней месяца (по `business_day_closures`).
- Прошедший месяц: если закрыты все дни, прогноз равен факту.
- Формулы остаются прежними: `Forecast = (Result / daysElapsed) × дней в месяце`, `Expected Profit = Forecast − Estimated − Extras − Collection + Other`.


## 4. Надёжность Collection

Сейчас расходы тянутся пачкой до 5000 строк и фильтруются по категории уже в браузере — при большом объёме часть строк может не попасть в отчёт.

Что делаем: фильтр по категориям группы `collections` выполняется на сервере внутри новой функции, лимита строк нет.

## 5. Курсы валют

Сейчас берётся последний по времени курс кассы, независимо от даты операции.

Что делаем: курс подбирается на дату строки из `fin_daily_rates` (курс на дату или ближайший предыдущий); если записи нет — последний курс кассы; если и его нет — фиксированный фолбэк (USD 2600, EUR 2800, GBP 3000, KES 17). Это касается бюджета (Estimated) и валютных расходов.

## 6. Прозрачность: подсказки «откуда цифра»

На каждой строке отчёта — иконка-подсказка с формулой и источником, например:

```text
Result (Live+Slots)  Только закрытые дни: Live + Slots − Players Card Balance
Collection           Расходы месяца в категориях группы Collections
Estimated Expenses   Бюджет месяца, пересчитанный в TZS по курсу на дату
Extra Expenses       Ручные строки отчёта + Approx Bonus 5%
Bonus 5%             5% от max(0, Result − Estimated) по каждому казино
Balance              Result + Other − Estimated − Extras − Collection
Expected Profit      Прогноз результата на месяц − Estimated − Extras − Collection + Other
```

Подсказки на английском (UI остаётся английским), доступны на десктопе (hover) и на мобильном (tap).

## Технические детали

- Новая SQL-функция `public.boss_monthly_report(uuid[], int, int)` — `SECURITY INVOKER`, `STABLE`, `SET search_path = public`; данные фильтруются существующими RLS-политиками (`fin_day_closing`, `expenses`, `fin_budget`, `fin_other_incomes`, `boss_report_extras`).
- Логика переносится из `src/hooks/use-boss-monthly-report.ts`; блоки live-fallback (`shifts`, `cage_slots_shifts`, `chip_snapshots_latest`) удаляются.
- Хук сохраняет прежние типы `Summary` / `DailyRow` / `BossMonthlyReport`, поэтому `monthly-report-panel.tsx` не переписывается — меняется только источник данных и добавляются подсказки.
- Инлайн-редактор Extra Expenses (`boss_report_extras`) не меняется.
- Версия приложения повышается.

## Что не меняется

Состав строк и колонок отчёта, формула Balance, логика Players Card Balance, бонус 5%, права доступа.
