# Company → Office Monthly Balance: автозаполнение из данных системы

## Что не так сейчас

- **Cage Office** не берётся из кошельков: это ручное поле «Start», сохранённое в браузере, плюс движения по расходам. Кошельков «офис» в базе не существует — есть только `cash`, `safe`, `mobile_money`, `bank`, привязанные к казино.
- **IN по казино** ищет расходы категории «collections»: за август таких всего 3 записи, поэтому колонки IN практически пустые.
- **Transfer** вычисляется догадкой (любой приход, кроме банка), хотя реальные переводы лежат парами out/in — считается не то.
- **Result** берёт только столы + слоты из закрытия дня, без бара, JP и Diff.
- **Bank** работает корректно.

## Целевая формула (одна строка = один день)

```text
IN (по казино)   = парные переводы: списание с кошелька казино → зачисление на офисный кошелёк
Cage Office      = остаток офисных кошельков (наличные + mobile money) на конец дня
Bank             = остаток банковских кошельков на конец дня
Expenses         = офисные расходы дня
Transfer         = переводы офис → казино (обратное направление пары)
OUT              = выплаты из компании (владелец / AK)
Money Total      = Cage Office + Bank
Balance          = Money вчера + IN − Expenses − Transfer − OUT − Money сегодня  (должен быть 0)
Result казино    = Столы + Слоты + Бар + JP ± Diff (как в Casino Monthly Balance)
```

Все цифры приходят из системы; вручную вносятся только сами движения денег — через существующий диалог кошельков (Money In / Money Out / Transfer). В самой таблице отчёта ничего не редактируется.

## Что делаем

1. **Признак офисного кошелька.** Добавляем флаг `is_office` в кошельки и переключатель в настройках кошельков (доступен финансовому менеджеру и выше). Отмечаем нужные сейфы и mobile money один раз — дальше отчёт считает сам.
2. **Cage Office из кошельков.** Остаток офисных кошельков на конец каждого дня = стартовый флоат + все проведённые движения по дату включительно. Ручное поле «Start» убираем: строка Start становится вычисляемой (остаток на конец предыдущего месяца), редактировать её не нужно.
3. **IN и Transfer из парных переводов.** Определяем направление по паре: казино → офис = IN (с разбивкой по казино), офис → казино = Transfer. Догадку по «любому приходу» убираем.
4. **OUT и Expenses.** OUT = выплаты из офисных кошельков наружу (collection / выплата владельцу). Expenses = офисные расходы дня. Уточняем классификацию, чтобы одна операция не попадала в две колонки.
5. **Result по казино** переводим на полный Fin Result: столы + слоты + бар + JP ± Diff, из тех же источников, что и Casino Monthly Balance, — цифры двух отчётов сойдутся.
6. **Сверка Balance.** Колонка Balance остаётся контрольной: не 0 — значит движение денег не внесено. При клике по ячейке показываем расшифровку компонентов дня.

## Технические детали

- Миграция: `fin_wallets.is_office boolean not null default false`; проставить флаг существующим офисным кошелькам.
- `src/hooks/use-office-balance-report.ts`: убрать параметр `startBalance`; считать `cage_office` как running-баланс кошельков с `is_office`; `bank` оставить по kind `bank`/`bank_account`; IN/Transfer определять по парам `transfer_out`/`transfer_in` с сопоставлением по сумме и дате; Result собрать из общего источника Fin Result.
- `src/pages/reports/OfficeBalanceReport.tsx`: строка Start только для чтения, панель расшифровки Balance, IN по казино из новых данных.
- Настройки кошельков: чекбокс «Office wallet».
- Демо-данные `src/lib/demo-report-data.ts` привести к новой структуре.
- Поднять версию в `package.json`.

## Сроки

Работа делится на два шага: (1) флаг офисных кошельков и Cage Office/Bank из кошельков, (2) IN/Transfer по парам и полный Fin Result. Оба шага — в рамках одной итерации после утверждения плана; после этого нужен ваш проход по августу, чтобы отметить офисные кошельки и проверить, что Balance по дням выходит в ноль.
