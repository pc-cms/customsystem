# Company → Daily Balance: старт с даты и автозаполнение из системы

## Идея

Один раз вносится стартовый баланс на выбранную дату (например 11/08). Дальше строка на каждый день появляется сама после закрытия бизнес-дня и подтягивает всё из системы. Ручной остаётся только одна операция: менеджер вносит фактические остатки кошельков и банка и нажимает **Record** — после этого баланс дня пересчитывается и сходится.

## Что не так сейчас

- **Cage Office** не берётся из кошельков: это поле «Start», сохранённое в браузере, плюс движения по расходам. Признака «офисный кошелёк» в базе нет — есть только `cash`, `safe`, `mobile_money`, `bank`, привязанные к казино.
- **IN по казино** ищет расходы категории «collections»: за август таких всего 3 записи, поэтому колонки IN практически пустые.
- **Transfer** вычисляется догадкой (любой приход, кроме банка), хотя реальные переводы лежат парами out/in.
- **Result** берёт только столы + слоты из закрытия дня, без бара, JP и Diff.
- Кнопка **Record** в Wallets уже есть, но пишет снимок только по офису и банку и никак не связана со строкой отчёта.
- **Bank** считается корректно.

## Целевая формула (одна строка = один бизнес-день)

```text
Cage Casino   = сумма закрытий касс дня по номиналам (Live Game + Slots)
Cage Office   = офисные кошельки на момент Record (снимок дня)
Bank          = банковские кошельки на момент Record (снимок дня)
IN (по казино)= парные переводы: кошелёк казино → офисный кошелёк
Transfer      = обратное направление пары: офис → казино
Expenses      = офисные расходы дня
OUT           = выплаты из компании (владелец / AK)
Diff          = chip difference + card balance дня
Result        = Столы + Слоты + Бар + JP ± Diff
Money Total   = Cage Casino + Cage Office + Bank
Balance       = Money вчера + Result + IN − Expenses − Transfer − OUT − Money сегодня  (0)
```

## Как это работает по дням

1. **Стартовая дата.** В настройках отчёта задаётся дата старта и стартовые суммы (Cage Casino, Cage Office, Bank). Значения хранятся в базе, а не в браузере, и служат строкой Start. До этой даты отчёт ничего не считает.
2. **Закрытие бизнес-дня.** После закрытия дня строка создаётся автоматически: Cage Casino берётся из закрытий касс по номиналам, Result и Diff — из закрытия дня, расходы и переводы — из уже внесённых операций.
3. **Пока Record не нажат** строка помечена как «ожидает подтверждения»: Cage Office и Bank показываются по последнему известному снимку, Balance подсвечивается как непроверенный.
4. **Record в Office Wallets.** Менеджер вносит фактические остатки, жмёт Record — снимок дня фиксируется, строка получает статус подтверждённой, Balance пересчитывается сразу, без перезагрузки.
5. **Balance** остаётся контрольным: не ноль — значит какое-то движение денег не внесено, при клике открывается расшифровка компонентов дня.

## Признак офисного кошелька

Добавляем флаг «Office wallet» в кошельки (переключатель в настройках, доступ финансовому менеджеру и выше). Отмечаем сейфы и mobile money один раз — дальше Cage Office и IN/Transfer считаются сами.

## Пересмотр закрытия кассы

Cage Casino должен приходить из закрытия смены по номиналам (Live Game + Slots), а не пересчитываться отдельно. Проверяем, что закрытие пишет итог по номиналам на бизнес-день в одном формате для обеих касс, и отчёт читает именно эту цифру — иначе две части системы будут давать разные суммы.

## Технические детали

- Миграция: `fin_wallets.is_office boolean not null default false`; таблица стартовых значений отчёта (casino-agnostic: дата старта + cage/office/bank); проставить флаг существующим офисным кошелькам.
- `useRecordDayBalance` (`src/hooks/use-day-balance-snapshot.ts`): писать снимок по кошелькам с `is_office` и банкам, помечать день как подтверждённый; после успеха — `invalidateFinance(qc)`.
- `src/hooks/use-office-balance-report.ts`: убрать параметр `startBalance` из аргументов, читать старт из базы; Cage Office/Bank — из `fin_day_balance_snapshot`; IN/Transfer — по парам `transfer_out`/`transfer_in` с сопоставлением кошельков; Result — полный Fin Result; добавить в строку `confirmed`.
- `src/pages/reports/OfficeBalanceReport.tsx`: строка Start только для чтения (правится в настройках), бейдж «Pending / Recorded» на строке дня, панель расшифровки Balance.
- Cage Casino: читать закрытия смен по номиналам за бизнес-день (Live + Slots), после проверки формата записи в закрытии.
- Демо-данные `src/lib/demo-report-data.ts` привести к новой структуре. Поднять версию в `package.json`.

## Порядок запуска

1. Флаг офисных кошельков + стартовые значения в базе + Record пишет снимок офиса и банка.
2. Cage Casino из закрытий по номиналам, IN/Transfer по парам, полный Fin Result, статус строки.
3. Ваш проход: задать дату старта и суммы, отметить офисные кошельки, за первый же день нажать Record и убедиться, что Balance выходит в ноль.
