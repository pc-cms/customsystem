# Miss Chips: строка Start Month с переносом итога

## Что делаем

1. На экране Miss Chips сверху появляется строка **START** (по номиналам и в TZS) = итог END прошлого месяца. Внизу вместо одного MONTH SUM две строки: **MONTH SUM** (только этот месяц) и **END = START + MONTH SUM**.
2. Перенос автоматический: END месяца становится START следующего. Отсчёт с сентября 2026 (сентябрь START = 0, октябрь START = итог сентября и т.д.). Ничего вручную вводить не нужно.
3. В финансах месяца (Wallets / Finance Breakdown / Monthly Report) Miss Chips учитывается как START + движение месяца — то же число, что END на экране.
4. Строка START показывается только при выборе целого месяца; при произвольном периоде экран как сейчас.

## Технические детали

- Новая SQL-функция `miss_chips_carry(casino_id, year, month)` → START по номиналам и TZS: сумма `closing_count.chip_miss_by_denom` / `chip_miss_total` закрытых смен с `business_date_of(opened_at)` от 2026-09-01 до дня перед началом месяца. Без новых таблиц и без записи данных — всё вычисляется, поэтому правки старых смен автоматически пересчитывают перенос.
- RPC `fin_balance_snapshot`: в блоке Miss Chips прибавить START (`incomes.missed_chips` = START + месяц), отдельным полем вернуть `missed_chips_start`.
- `src/pages/MissChips.tsx`: запрос START через RPC, строки START / MONTH SUM / END.
- Monthly Report/Wallets читают `incomes.missed_chips` — фронт там не меняется.
- Поднять версию в `package.json`.

## Внимание

Это меняет месячный результат: Miss прошлых месяцев снова попадает в доходы следующего месяца (накопительно). Если нужно, чтобы в доходы шла только разница месяца, а START был лишь справочным — скажите до утверждения.
