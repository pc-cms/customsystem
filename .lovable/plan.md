# Импорт клиентской базы Dodoma из Customers.xlsm

## Что в файле

Файл содержит два листа:

- **CustomBackUp** — 44 259 строк транзакций (In/Out) за период 20.03.2025 – настоящее время, по столам AR1/AR2/BJ и т.д., с суммами в TZS/USD/EUR/GBP/KES, чипами и Drop.
- **Analizer** — сводная таблица по игрокам: Total Drop, Total Result, Hold %. 831 строка (включая строку Grand Total).

**Уникальных клиентов: 802** в транзакциях, плюс 1 имя, встречающееся только в сводке (`HUANG HUANG  BABU`) — итого **803**.

Сейчас в Dodoma в системе только 2 игрока — служебные `DOD LIVE GAME` и `DOD FLOOR`.

## Что сможем внести

Полностью переносимо для всех 803 записей:

- Имя игрока (единственные персональные данные в файле)
- Привязка к казино Dodoma
- Тип игрока — table (все транзакции по столам)
- Категория — Normal, статус — Active, верификация — Unverified

## Чего в файле нет и внести нельзя

В файле **отсутствуют**: телефон, номер документа, дата рождения, фото, гражданство, адрес, категория/тир игрока, дата регистрации. Соответственно:

- Никого нельзя завести как Verified — все войдут как Unverified и будут проходить проверку на ресепшене при первом визите.
- Категории (Casino/Diamond/Platinum/Gold) проставить не из чего — все получат Normal. При желании можно проставить автоматически по обороту из листа Analizer (см. опции ниже).

## Проблемные записи (требуют решения)

1. **402 имени из одного слова** — это прозвища, а не ФИО (`WASIF`, `SHANI`, `EDIGAR`). Заносятся как имя, фамилия остаётся пустой.
2. **Описательные клички вместо имён — около 150 записей** с суффиксом `CHINESE` (`KELVIN CHINESE`, `PETER CHINESE`), а также `MAMA FAA`, `MR FUU`, `WHO`, `RANGO CHINESE`. Формально валидны, но это не паспортные имена.
3. **14 сомнительных коротких записей**: `AJ`, `BO`, `GO`, `LI`, `TU`, `VU`, `WU`, `XI`, `XO`, `XU`, `YE`, `YI`, `YU`, `PATEL 2`. Скорее всего опечатки или временные записи кассира.
4. **101 пара похожих имён — вероятные дубли одного человека**: `ABDUL RAZAK` / `ABDULRAZAK`, `BAO WANG` / `BAOWANG` / `BAON WANG`, `CHEN TEN` / `CHEN TENG`, `ERIC CHINESE` / `ERICK CHINESE`, `BAOEN HUAN` / `BAOEN HUANG` и т.д.
5. **93 клиента с единственной транзакцией** и ещё 266 с 2–5 транзакциями — разовые посетители.
6. **27 строк с датами из будущего** (до 2029 года) — ошибки ввода в Excel. На импорт имён не влияют, влияют только при переносе истории.

## План работ

1. Нормализовать имена: убрать двойные пробелы, привести к единому регистру (Title Case), разбить на имя/фамилию по первому пробелу.
2. Импортировать 803 игрока в базу Dodoma со статусом Active / Unverified / Normal.
3. Явные технические дубли (различие только в пробеле/дефисе, напр. `ABDUL RAZAK` = `ABDULRAZAK`) склеить в одну запись при импорте.
4. Неочевидные пары (101 пара) **не** склеивать автоматически — оставить как отдельных игроков; менеджеры смогут объединить их через существующий инструмент объединения двойников.
5. Отдать список из 14 сомнительных коротких записей и списка похожих пар отдельным файлом для ручной проверки.

## Опции, которые нужно подтвердить

- **Разовые клиенты**: заносить всех 803 или отфильтровать тех, у кого 1 транзакция (минус 93 записи)?
- **Категории**: оставить всем Normal или проставить тир автоматически по обороту из Analizer?
- **История игры**: переносить ли 44 259 транзакций и Total Drop/Result по каждому игроку, или только имена? История — отдельная задача существенно большего объёма: даты в файле частично битые, столы Dodoma в системе называются иначе (P1–P5 вместо OP1–OP4), потребуется маппинг столов и разбор бизнес-дат.

## Технические детали

- Целевая таблица — `players`, casino_id Dodoma. Поле `full_name` вычисляемое, заполняются `first_name` / `last_name`.
- Импорт одним пакетным запросом с дедупликацией по нормализованному имени.
- Служебные аккаунты `DOD LIVE GAME` / `DOD FLOOR` не затрагиваются.
- Файл в репозиторий не копируется, читается из загрузок только на время импорта.
