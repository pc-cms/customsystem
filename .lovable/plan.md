# Attendance → Payroll (Mbeya) + экспорт в Excel

## Что показала проверка

Данные по Mbeya в базе есть и корректны: за август 331 запись по персоналу и 392 по дилерам, все привязаны к сотрудникам Mbeya, без «сирот». Функция месячной посещаемости для Mbeya возвращает 1674 строки, из них 722 с часами по 51 сотруднику — то есть экран Monthly Attendance получает данные.

Реальная причина «не подтягивается в Payroll»: пересчёт зарплатного периода берёт из посещаемости только три величины — часы в праздники, дни праздников и прогулы (код `A`). В Mbeya за август нет ни одного `A` и нет праздников, поэтому в периоде Mbeya (53 строки, статус draft) все поля из посещаемости равны нулю. Отработанные часы и дни, а также off days вообще нигде не переносятся — ни в Mbeya, ни в других филиалах.

Отдельно: в Mbeya посещаемость вводят числами (8, 11), без кодов M/N. Night days остаются ручным вводом — так и оставляем.

## Что сделаем

1. **Расширить перенос посещаемости в Payroll** (для всех филиалов):
   - Missing days — как сейчас (код `A`).
   - Отработанные часы и отработанные дни — новые справочные колонки в строке периода, заполняются автоматически.
   - Off days / off days hours — считаем переработку: дни сверх нормы (`working_days` из настроек) и часы этих дней. Значения остаются редактируемыми вручную: пересчёт заполняет их, HR может поправить.
   - Night days — не трогаем, только ручной ввод.
2. **Показать новые колонки** в таблице Payroll · Period (Worked days, Worked hours) как read-only справку рядом с существующими.
3. **Кнопка «Export to Excel»** на странице Monthly Attendance — доступна во всех филиалах и для всех ролей, которые видят страницу. Файл: сетка «сотрудник × дни месяца» с кодами/часами, колонки итогов (Hours, Days worked, Leave, Holiday hours, OT), группировка по департаментам, шапка с названием казино и месяцем. Имя файла вида `Attendance_Mbeya_2026-08.xlsx`.
4. После правок — прогнать пересчёт периода Mbeya 08/2026 и проверить, что цифры появились.
