# Breaklist clear failed: временный ID "temp-..."

## Причина (подтверждена кодом)

Когда оператор ставит роль в ячейку, кэш сразу получает запись с временным ID `temp-<timestamp>` (`use-dealers.ts:501`, оптимистичное обновление), а настоящий UUID приходит позже с ответом сервера. Если оператор сразу же очищает эту ячейку (или сервер ещё не вернул обновлённый список — медленная сеть, офлайн), `useClearBreaklistCell` шлёт `.eq("id", "temp-...")` в колонку типа `uuid` — база отвечает `invalid input syntax for type uuid`.

То же потенциально может случиться в `useLockBreaklistCell` (тоже работает по `id`).

## Что чиню

1. `useClearBreaklistCell` (`src/hooks/use-dealers.ts`): если `id` начинается с `temp-` — вместо поиска по `id` искать реальную строку по ключу `(casino_id, dealer_id, date, time_slot)`:
   - строка нашлась → очистка по найденному реальному UUID, лог в `breaklist_logs` пишется с реальным ID;
   - строки нет (сервер ещё не успел сохранить) → короткий повтор запроса (до ~2 с), потом понятная ошибка "cell is still saving, try again", а не падение в Postgres.
2. `useLockBreaklistCell`: та же защита — при `temp-` ID резолвить реальный UUID по ключу ячейки перед update.
3. Поднять версию в `package.json`.

## Технические детали

- Файл: `src/hooks/use-dealers.ts` — только эти две мутации, остальная логика очистки (CLR-роль, логи, оптимистичный откат) не меняется.
- Изменений в базе не требуется.
- Проверка: typecheck + сценарий «поставить роль и тут же очистить» не должен давать uuid-ошибку.
