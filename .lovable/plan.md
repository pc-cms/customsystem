# Ускорение: Профиль игрока, Брейк-лист, Player Statistics, Офис

## 0. Профиль игрока и фото (сейчас 3–5 секунд)

- Карточка профиля открывается сразу: сначала показываем уже загруженные данные игрока из списка, остальные блоки (визиты, транзакции, расходы, группы, заметки) подтягиваются по мере готовности и не блокируют открытие.
- Запросы профиля перестают тянуть все поля подряд — берём только те, что реально показаны на экране.
- Блоки профиля, которые не видны сразу (история, расходы, группы), запрашиваются только при открытии своей вкладки.
- Фото: ссылки на изображения запрашиваются пачкой и кэшируются на час, миниатюра показывается сразу, изображение грузится лениво. Повторный вход в профиль показывает фото мгновенно из кэша.
- Замеряем время открытия профиля до и после; цель — открытие меньше секунды, фото — без ожидания белого экрана.



## 1. Сегодня — мгновенно, без фоновых догрузок

Брейк-лист и Player Statistics при выбранном сегодняшнем дне запрашивают только сегодняшний день:

- Никаких параллельных запросов за неделю/месяц во время работы с сегодняшним экраном.
- Запросы за сегодня отправляются сразу при входе, данные из кэша показываются мгновенно, обновление приходит поверх.
- Player Statistics за сегодня перестанет тянуть широкие выборки: транзакции, чип-трансферы и корректировки читаются одним окном 07:00–07:00 текущего дня с ограничением на выборку колонок (сейчас читается `select *`).
- Цель отклика — до 300 мс на запрос за сегодня. Проверим замером на реальном филиале до и после и покажем цифры.

## 2. Неделя и месяц — только в фоне

- Более широкие периоды грузятся отдельно и с низким приоритетом, после того как экран за сегодня уже отрисован.
- Предзагрузка недели и текущего месяца для Офиса, Брейк-листа и Player Statistics запускается в простое браузера, а не одновременно с открытием экрана.
- При переключении дня/месяца текущие цифры остаются на экране, новые подставляются по готовности (уже сделано на прошлом шаге, здесь дополняем предзагрузкой).
- Фоновая загрузка останавливается, если вкладка не активна.

## 3. Виртуализация списков в Офисе

- Списки Офиса, которые уже используют общий компонент таблицы, начнут окно-рендер с меньшего порога (примерно 80 строк вместо 200) — прокрутка месяца перестанет лагать.
- Две таблицы, собранные вручную и не поддерживающие окно-рендер (страница Wallets: список движений и месячная сетка), переводятся на общий компонент с виртуализацией; внешний вид и цифры не меняются.
- История расходов в Офисе рендерится порциями видимой области.

## 4. Индексы и запросы в базе

Проверено по текущей базе — не хватает:

- `fin_money_change`: нет ни одного индекса кроме первичного ключа, а Офис фильтрует по филиалу и дате → добавляем индекс по (филиал, дата, время создания).
- `shifts`: индекса по (филиал, время открытия) нет, а месячная сводка Day Closings читает смены за диапазон → добавляем.
- `transactions`: добавляем индекс под основной запрос Player Statistics — филиал + время создания, только для неотменённых записей.
- Брейк-лист, расходы, кошельки, JP/Transactions, drop-кэш, зоны и средние ставки — индексы уже есть, дубли не создаём.

После добавления прогоняем планы запросов (EXPLAIN ANALYZE) на реальных данных и подтверждаем, что индексы используются и full scan ушёл.

## Технические детали

- Клиент: `src/hooks/use-dealers.ts` (breaklist), `src/pages/PlayerStatistics.tsx`, `src/hooks/use-fin.ts`, `src/hooks/use-other-incomes.ts`, `src/pages/office/*`, новый модуль фоновой предзагрузки на `requestIdleCallback` + `queryClient.prefetchQuery`.
- Виртуализация: `src/components/ui/smart-table.tsx` (порог), `src/pages/finances/FinancesWalletsPage.tsx` (две ручные таблицы), `src/pages/Expenses.tsx`.
- База: три новых индекса миграцией (`fin_money_change`, `shifts`, `transactions` partial), затем EXPLAIN ANALYZE по каждому из целевых запросов.
- Замеры отклика берём из уже работающей панели метрик запросов в Admin Logs (до/после).

## Границы

- Формулы, отчёты, права доступа и исторические данные не трогаем.
- Офлайн-очередь кассиров и текущая частота обновления активных экранов не меняются.
- Публикация — только по отдельной команде.
