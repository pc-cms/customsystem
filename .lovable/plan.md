# CMB: универсальный drill по деньгам + правки колонок

## Проблемы (проверено в коде и данных)

1. **Cage Casino: цифра и разбивка из разных источников.** Значение ячейки считается из физических пересчётов кошельков (`cage_table` / `cage_slot` / `safe`), а панель — из закрытий смен (`closing_count.cash`, `closing_count.mobile`, cashless-провайдеры, инвентарь слот-кассы). Отсюда 8 944 000 + 5 110 000 = 14 054 000 вместо 10 000 000.
2. **Дубликаты провайдеров.** «Mobile Money» и «Cashless» — это одни и те же каналы (AirTell / AirTel, Tigo, Halo, Mpesa), показанные двумя блоками с разным написанием.
3. **Разный вид панелей.** Cage Manager и Bank уже на `DrillTable`, Cage Casino — на старом `CurrencyCashTable`.
4. **Bank USD не кликабельна** — в рендере ячейки стоит ранний возврат (подсказка в USD) до проверки drill-колонок.
5. **Grand Total (Wallets) ≠ Money.** По Аруше Grand Total = 69 161 039 TZS (11/08), пересчёт по датам даёт 75 236 825 (10/08) и 69 161 039 (11/08); значения 45 480 286 из колонки Money среди них нет — набор кошельков/срез в CMB не совпадает с Wallets.

## Что делаем: один универсальный drill для всех денежных колонок

Единый компонент `MoneyDrill` с фиксированной структурой (везде одинаковой):

```text
CASH                  UNITS      RATE        TZS
  TZS
  USD
  EUR
  GBP
  KES
MOBILE MONEY
  AirTell
  Tigo
  Halo
  M-Pesa
BANK           (только там, где есть банковские кошельки)
  <счёт>
TOTAL                                    = значение ячейки
```

Правила подключения кошельков:

- **CASH** — кошельки с наличными, сгруппированные по валюте (TZS / USD / EUR / GBP / KES). Units — в своей валюте, Rate — курс дня, TZS — конвертированная сумма.
- **MOBILE MONEY** — кошельки вида `mobile_money`, названия нормализуются в фиксированные 4 канала (AirTell, Tigo, Halo, M-Pesa); всё, что не распознано, идёт строкой «Other». Отдельного блока «Cashless» больше нет — это те же каналы.
- **BANK** — кошельки `bank` / `bank_account`, по счёту и валюте.
- Строка всегда показывается, даже если 0 (текущее правило CMB: 0, а не точка).
- Источник значений один и тот же везде — последний физический пересчёт кошелька на выбранную дату. Итог панели всегда равен цифре в ячейке.

Где применяется:

| Колонка | Что попадает в drill |
| --- | --- |
| Cage Casino | кошельки кассы казино (`safe`, `cage_table`, `cage_slot`): CASH + Mobile Money + Slots cage |
| Cage Manager | офисные кошельки (`cash`, `mobile_money`, `office_safe`, `*_reserve`): CASH + Mobile Money |
| Bank TZS / Bank USD | банковские кошельки соответствующей валюты |
| Money | все три корзины сразу: Cage Casino + Cage Manager + Bank |

## Остальные правки

- **Bank USD** делаем кликабельной (подсказка в USD сохраняется).
- **Колонку Collections** убираем полностью (заголовок, значения, печать/экспорт).
- **Сверка Money.** Money = Cage Casino + Cage Manager + Bank по тем же пересчётам, что и Grand Total на Wallets за ту же дату. Первым шагом выводим сверку по каждому дню (корзина → кошелёк → дата последнего пересчёта), локализуем расхождение (правило бизнес-дня при выборе последнего пересчёта, отсечка Start или кошелёк вне корзин) и правим отбор. Причина ещё не подтверждена — поэтому сверка идёт до правки.

## Технические детали

- Новый компонент `src/components/reports/MoneyDrill.tsx` поверх существующего `DrillTable` (формат Name / Units / Rate / TZS) — используется всеми денежными колонками.
- В `src/hooks/use-daily-balance-report.ts` строится единая структура `money_detail` по каждому дню из `countAt(wallet, date)` (тот же helper, что считает `cageCasinoRunning`), с разбивкой по корзинам, валютам и провайдерам; старый `cage_detail` из `closing_count` удаляется.
- Нормализация провайдеров — по существующему маппингу из `CurrencyCashTable.tsx` / `use-cashless.ts`.
- В `src/pages/reports/DailyBalanceReport.tsx`: все ветки drill заменяются на `MoneyDrill`; ранний возврат для `bank_usd` заменяется вариантом с drill-обработчиком; `money_total` добавляется в drill-колонки; колонка `collections` удаляется из конфигурации и связанных списков.
- Повышение версии приложения.
