# Зафиксировать цифры кассовых отчётов

## Что подтверждено

- Сейчас на бумаге нет сохранённого экземпляра отчёта: при каждом открытии и повторной печати цифры заново собираются из текущих смен, расходов, транзакций, пересчётов фишек, курсов и списка кошельков.
- Экранный предпросмотр и скрытая область печати создаются отдельно; часть данных загружается асинхронно уже внутри листов. Поэтому печать может стартовать раньше полной загрузки и получить другой набор цифр.
- Итоговый лист особенно нестабилен: он каждый раз повторно читает все Live Game и Slots смены за дату, расходы и cashless-операции. Изменение любой из этих записей после закрытия меняет повторную печать.
- В приложенном отчёте Arusha за 05/09/2026 первый лист уже имеет статус `CLOSED — APPROVED`, а итоговый и Live Game листы всё ещё показывают `DRAFT — GBT APPROVAL PENDING`. Это подтверждает, что четыре листа формируются не как один зафиксированный комплект.
- Отдельной таблицы для неизменяемого снимка кассового отчёта сейчас нет; сохранены только отдельные части закрытия смены.

## Шаг 0 — перепечатать корректные отчёты сейчас

Все смены уже закрыты, поэтому начинаем с разовой фиксации по факту:

- Для каждой закрытой смены собрать комплект листов «по состоянию на момент закрытия»: транзакции, переводы, пересчёты фишек, cashless и расходы берутся с ограничением по времени закрытия смены, а не по «сейчас».
- Сверить полученные комплекты с уже подписанными бумажными отчётами (в том числе Arusha 05/09/2026) и подтвердить расхождения перед сохранением.
- Сохранить их как неизменяемые снимки, после чего перепечатка из истории берёт готовый снимок: цифры перестают меняться между предпросмотром и печатью и между двумя печатями.
- Все четыре листа комплекта получают единый статус (закрыто/подтверждено), а не смесь «CLOSED» и «DRAFT», как в приложенном отчёте.

## Решение

1. **Один неизменяемый снимок на закрытие**
   - При подтверждении менеджером backend в одной операции закрывает смену и сохраняет полный набор данных печатных листов: все числа, строки таблиц, курсы, названия кошельков, статусы и подписи.
   - Снимок получает номер версии и контрольную сумму; обновление или удаление снимка запрещается политиками и триггером.

2. **Один источник для предпросмотра и печати**
   - После закрытия и экран, и печатная область получают один и тот же сохранённый объект.
   - Печать становится доступна только после полной загрузки снимка. Никаких повторных запросов к текущим расходам, транзакциям, кошелькам или таблицам во время печати.
   - Все четыре листа строятся одним комплектом с единым статусом и идентификатором версии.

3. **Правильный момент фиксации**
   - Отдельный лист Live Game фиксируется при закрытии Live Game менеджером; Slots — при закрытии Slots менеджером.
   - Итоговый четырёхлистный комплект фиксируется, когда обе кассы за бизнес-день закрыты. До этого итоговый лист явно остаётся предварительным и не считается финальным комплектом.
   - Автоматическое обязательное окно печати после закрытия сохраняется, но открывается только по готовому снимку.

4. **Исправления без перезаписи истории**
   - Повторная печать всегда использует исходный снимок.
   - Если менеджер официально переоткрывает смену и закрывает её заново, создаётся новая ревизия; старая остаётся в истории и помечается заменённой.
   - Текущий режим локального «Reprint with edits» не сможет выдавать изменённый лист как оригинал: такие варианты будут явно отдельной черновой копией либо будут исключены из финальной печати.

5. **Переход для существующих смен**
   - Для закрытых смен без снимка создать однократный legacy-снимок из сохранённых данных закрытия, не пересчитывая его при следующих просмотрах.
   - Отдельно сверить Arusha 05/09/2026 с приложенным PDF и текущими сохранёнными значениями; зафиксировать найденную корректную ревизию.

6. **Проверка**
   - Автотест: предпросмотр и распечатанный HTML имеют одинаковую контрольную сумму данных.
   - Проверить Live, Slots, Chips и Total во всех филиалах, включая нулевые кошельки, валюты/курсы, расходы, cashless и результаты столов.
   - Проверить, что изменения исходных записей после закрытия не меняют старый отчёт, а переоткрытие создаёт новую ревизию.
   - Прогнать печать: строго 4 листа, заданные ориентации, без запуска до полной загрузки данных.

## Технические детали

- Новая защищённая таблица снимков с явными `GRANT`, RLS, уникальностью по филиалу/дате/типу/ревизии и запретом `UPDATE/DELETE`.
- Backend-функция формирует канонический JSON отчёта и журналирует создание/замену снимка триггером.
- Компоненты листов становятся чистыми: получают готовые данные через props и больше сами не обращаются к базе.
- Для открытой смены остаётся отдельный live-preview; он визуально помечен как предварительный и никогда не используется как финальный печатный документ.
