# Проводки августа 1 сентября + открытие нового месяца

## Что сейчас происходит

- Серверная функция офисного расхода уже принимает дату проводки (`p_business_date`), но экран Office → Expenses всегда подставляет сегодняшний бизнес-день и не даёт его изменить. Поэтому августовский расход падает в сентябрь.
- Закрытие месяца (Close Month Wizard) — отдельный ритуал: сбор (Collection) по кошелькам + новый Starting Float + блокировка отчёта месяца.
- В журнале закрытий сейчас всего две записи: Arusha (июль) и Mwanza (август, закрыт 2 августа — похоже, помечен не тем месяцем). Остальные казино август ещё не закрывали.

## Варианты решения даты

**Вариант A (рекомендуемый) — поле «Posting date» в форме расхода**
- В диалоге добавления расхода появляется дата проводки, по умолчанию — сегодняшний бизнес-день.
- Можно выбрать любую дату в пределах текущего или предыдущего месяца, пока предыдущий месяц не закрыт.
- Если выбрана дата не сегодняшняя — рядом жёлтая пометка «Backdated to 31/08/2026».
- Доступно ролям finance_manager / general_manager / super_admin; обычный manager вводит только сегодняшним днём.

**Вариант B — режим «Закрыть август»**
- Отдельная кнопка-переключатель в Office: «Posting to August» (баннер на весь экран, пока включён). Все создаваемые расходы/доходы получают дату 31/08.
- Автоматически выключается после закрытия месяца.
- Меньше кликов при большом объёме проводок, но выше риск забыть выключить (частично снимается баннером).

**Вариант C — только ручное исправление задним числом**
- Ничего не менять в форме, а после ввода править дату записи через уже существующий финансовый аудит-редактор.
- Быстрее всего внедряется, но каждая запись правится дважды и создаёт лишние строки в аудите.

## Порядок работы с новым месяцем (в любом из вариантов)

1. Довести все августовские расходы/доходы с датой августа.
2. Проверить Monthly Report за август (Result / Paid / Pending) — цифры должны сойтись.
3. Запустить Close Month за 8/2026: шаг 1 — Collection по кошелькам, шаг 2 — новый Starting Float (обычно 0 или согласованная сумма), шаг 3 — Confirm & Lock.
4. После блокировки августа форма расхода перестаёт предлагать августовскую дату — весь ввод идёт в сентябрь.
5. Отдельно поправить некорректную запись закрытия Mwanza (месяц 8, закрыт 2 августа) — иначе август будет считаться уже закрытым.

## Техническая часть

- `src/pages/Expenses.tsx`: `effectiveDate` перестаёт быть жёстко привязан к `businessDate`; добавляется управляемое поле даты в черновой строке/диалоге, значение уходит в существующий параметр `business_date`.
- Ограничение диапазона дат считается по `fin_month_closures` (месяц закрыт → даты этого месяца недоступны) и по роли пользователя.
- Тот же принцип по желанию распространяется на Office → Tips & Bonuses, Transactions (Commissions), JP — они используют собственные даты периода.
- Серверных изменений не требуется: `create_office_expense` уже пишет переданный `business_date`. Дополнительно можно добавить в RPC проверку «месяц закрыт → запрет», чтобы обойти форму было нельзя.
