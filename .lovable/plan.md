# Table Tracking: статус столов за прошлые дни

## Проблема

При листании назад по датам (вчера, позавчера…) карточки столов показывают бейдж `Open` и зелёную точку. Это статус «прямо сейчас», а не состояние на выбранный день.

Проверено: в таблице `gaming_tables` есть только одно поле `status` (`open`/`closed`) — это текущий живой флаг, истории статуса по датам в базе нет. Поэтому страница за любую дату рисует сегодняшнее состояние.

## Решение

Смотрим на бизнес-день: если выбранная дата не равна текущему бизнес-дню, день уже завершён и все столы по факту закрыты. Значит для прошлых дат показываем `Closed` (серый бейдж, красная точка) независимо от живого флага.

## Что меняется

`src/pages/Tables.tsx`:
- Ввести `displayStatus = effectiveDate === businessDay ? table.status : "closed"` и использовать его в карточке стола (бейдж, цвет точки, кликабельность, hover).
- Кнопки действий (Reopen / открытие рассадки) для прошлых дат не показываются — они и сейчас завязаны на `isOpen`, поэтому просто перейдут на `displayStatus`.
- Сводные блоки, считающие «открытые столы» для операций (Open All и т.п.), остаются на живом `status` — они действуют только на сегодня.

`src/pages/TableTracker.tsx` и панели (`ChipCountPanel`, `HeadCountPanel`): фильтр «показывать стол, если он открыт ИЛИ есть данные за дату» остаётся, но для прошлых дат берётся только критерий «есть данные за дату», чтобы в исторической сетке не всплывали столы, которые открыты сегодня, но в тот день не работали.

## Технические детали

Изменения только во фронтенде и презентационном слое; схема БД и бизнес-логика не трогаются. Никакой новой таблицы истории статусов не заводим — при необходимости настоящей истории (кто и когда закрыл стол в конкретный день) это отдельная задача с миграцией.
