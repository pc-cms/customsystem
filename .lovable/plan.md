# ACE Analytics: рабочая структура интерфейса

## Цель
Разделить текущий экран на две понятные зоны и привести рабочие вкладки к стандартному стилю CMS, не меняя сборщик, расписания, финансовый импорт или формулы метрик.

## Что будет сделано

### 1. ACE — рабочая зона филиала
- Переименовать основной экран в **ACE** и убрать большую тестовую шапку, технический бейдж и общий переключатель филиалов.
- Брать филиал только из текущего разрешённого контекста CMS; обычный пользователь не сможет выбирать другой филиал.
- Оставить вкладки: **Consolidated**, **Players**, **EGM Live**, **Reports**, **Jackpots**.
- Упростить верхнюю часть до стандартного заголовка CMS, вкладок и локальных элементов управления каждой вкладки.

### 2. ACE Control — Super Admin
- Добавить отдельный экран **ACE Control**, доступный и видимый только Super Admin.
- Перенести туда общую сводку по филиалам и **System**: состояние подключений, последнюю синхронизацию, покрытие истории, доступность отчётов и сохранённые ACE periods.
- Не добавлять управляющих действий для collector/imports — только чтение существующих данных.

### 3. Consolidated
- Заменить неясный общий Live/Closed фильтр на три режима: **Current day**, **Month**, **Closed period**.
- **Current day** показывает текущий business day и обновляется автоматически.
- **Month** показывает строки по дням: Date, Drop, Handle, IN, OUT, Result, Games, Players, EGMs, Jackpot.
- **Closed period** выбирается из реально сохранённых ACE period/capture данных; отображаются дата/диапазон, время начала/окончания при наличии и состояние закрытия.
- KPI сделать выше и компактнее: только название и значение, без внутренних подсказок.
- Сохранить текущие формулы и отсутствие выдуманных значений.

### 4. Players
- Перестроить таблицу в две визуальные группы, близко к Player Tracking:
  - идентификация: ACE ID, Player, Card/identity, Visits, Last activity;
  - статистика: Drop, Handle, IN, OUT, Result, Games, Avg Bet, Jackpot.
- Использовать существующие стили чисел, строк и подсветок CMS.
- Last activity брать из уже сохранённых daily/transaction данных; если данных недостаточно — показывать `N/A`, не выдумывать.
- Связывание ACE ID оставить только внутри Player profile: один ACE ID, Branch, Link, подтверждение Unlink; никаких comma-separated полей.

### 5. EGM Live
- Убрать филиал из таблицы и фильтров рабочего branch-экрана.
- Оставить floor-monitoring поля: Position, State, Player, Active Credit, Game, Last Bet, Last activity.
- Сохранить автоматическое обновление раз в 25 секунд.
- KPI сделать компактными и без поясняющих подписей.

### 6. Reports
- Дать понятный выбор календарного диапазона From/To и типа **EGM Report / Jackpot Report**.
- Заменить технические названия Captures/Report Content на понятный список сохранённых ACE periods и открытый отчёт.
- Для выбранного диапазона показывать сохранённые строки ACE, totals только из суммируемых числовых колонок и экспорт фактического содержимого.
- Не пересчитывать сохранённые snapshot-значения. Если выбран диапазон с несколькими отчётами, агрегировать только совместимые исходные колонки, сохраняя возможность открыть отдельный period.

### 7. Jackpots
- Показать Player, ACE ID, EGM, Jackpot, Amount, Date/time.
- Использовать существующую связь identity, а при её отсутствии — подготовить безопасный read-only поиск по сохранённым EGM/time данным без записи или изменения исходных jackpot rows.
- Если однозначной сессии нет, Player остаётся `N/A`.

## Технические детали
- Переиспользовать `PageHeader`, `Tabs`, `FilterBar`, `SmartTable`, существующие календарные popover-компоненты и семантические цвета CMS.
- Разнести страницу на branch workspace и Super Admin control route; обновить меню и route mapping без изменения collector/cron/finance.
- Существующие RPC и таблицы остаются источником метрик. Для ACE periods сначала использовать сохранённые `ace_egm_reports` / `ace_jackpot_reports` (`period_from`, `period_to`, `period_label`, `captured_at`, `raw_data`).
- Если start/end/closed status отсутствуют в сохранённых полях, UI честно показывает `N/A`; новые исторические данные и collector не добавляются.
- Канон неизменен: Drop = EGM IN; Handle = ACE turnover; Result = IN − OUT; Jackpot отдельно.
- Проверить типы, тесты, production build и branch/super-admin отображение в браузере.

## Ограничение доступа
Сейчас политики данных ACE разрешают чтение только Super Admin. В этом проходе интерфейс и запросы будут branch-scoped, но доступ обычных ролей к самим данным не включается, потому что это потребовало бы изменения backend-политик. ACE Control останется строго Super Admin.
