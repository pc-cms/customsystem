# Wallets: кнопки Add money / Take money — починка + новая логика

## Почему сейчас ошибка

Диалог записывает движение с типом `adjustment_in` / `adjustment_out`. База принимает только:
`income`, `expense`, `change_in`, `change_out`, `transfer_in`, `transfer_out`, `reversal`, `adjustment`.
Поэтому любое сохранение Add / Take money отклоняется базой и появляется красный тост. Transfer работает — его типы разрешены (в базе есть строки transfer_in/out и ни одной adjustment_in/out).

## Как должно работать (по вашему описанию)

Add / Take money = чистая коррекция ФАКТА (Actual), как физический пересчёт:

```text
Actual 100 000  →  IN 10        →  Actual 100 010
Actual 100 010  →  OUT 50 000   →  Actual  50 010
```

- Не расход, не доход, не влияет на Expected (ожидаемый/книжный баланс).
- Влияет только на Actual, ровно как физический пересчёт кошелька.
- Разница между Expected и Actual (Variance) сама подтянется — это и есть смысл коррекции.
- Запись в транзакциях остаётся: видно кто, когда, сколько, комментарий.

## Что делаем

1. Кнопка IN / OUT перестаёт писать движение денег в леджер. Вместо этого она берёт последний физический факт по кошельку и сохраняет новый физический пересчёт: `новый Actual = текущий Actual ± сумма`. Используем тот же механизм, что и инлайн-пересчёт на странице Wallets (`fin_save_wallet_count`), поэтому цифры и история пересчётов остаются в одном формате.
2. Параллельно пишем строку в журнал движений с типом `adjustment` (этот тип уже разрешён базой и уже исключён из расчёта Expected) — только для аудита: сумма, направление, дата, автор, комментарий, купюры.
3. В диалоге меняем подписи, чтобы не вводить в заблуждение: показываем «Actual becomes: 100 010 TZS» вместо «Wallet increases by». Явная пометка: not income / not expense, affects Actual only.
4. Transfer в этом же диалоге оставляем как есть — он реально двигает деньги между кошельками и должен влиять на Expected.
5. Ошибки базы выводим текстом в тосте, чтобы подобная проблема сразу читалась.

## Технические детали

- Диалог перестаёт вставлять `adjustment_in` / `adjustment_out` в `fin_wallet_tx`; вместо этого вызывает `fin_save_wallet_count` с посчитанным новым значением факта, плюс аудит-строка `kind = 'adjustment'`.
- `fin_balance_snapshot` уже исключает `kind = 'adjustment'` из суммы движений — значит Expected не сдвинется, а Actual берётся из `cash_count_snapshots`, куда пишет `fin_save_wallet_count`. Изменения SQL не требуются.
- Для валют, отличных от TZS, курс берём той же логикой, что и инлайн-пересчёт (USD → `usdRate`, иначе `fin_daily_rates`).
- Клиентские правила знаков (`wallet-tx-sign.ts`, `use-fin.ts`, `use-wallet-day-grid.ts`) чистим от несуществующих `adjustment_in/out`.
- Версия приложения → 1.3.681.
