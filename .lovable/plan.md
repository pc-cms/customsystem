# Откат ограничений доступа (пункты 1, 2, 3, 5, 6, 7)

Возвращаем прежнюю системную модель: сеть из 4 казино работает как единое целое, менеджеры и выше видят всё, блэклист общий. Оставляем только пункт 4 (лицензия — по своему казино) и фиксируем остальное как «принятые решения», чтобы сканер безопасности больше не блокировал публикацию этими пунктами.

## Что вернётся

1. **Визиты игроков (casino_visits)** — снова видны всем сотрудникам сети.
2. **Drop-кэши (по игрокам и столам)** — снова глобальное чтение, сводные отчёты по сети работают у всех.
3. **Теги игроков и дневные зоны** — снова глобальное чтение.
4. **Лицензия казино** — остаётся ограниченной своим казино (по твоему решению, не меняем).
5. **Роли уровня «менеджер и выше» снова видят всю сеть автоматически**: `manager`, `shift_manager`, `finance_manager`, `general_manager`, `boss`, `surveillance`, `super_admin`. `hr` в этот список не входит — HR работает только по назначенным казино.
6. **Явные доступы на все 4 казино** проставляются перечисленным выше пользователям, чтобы вход и переключение казино работали независимо от роли. Пятое казино при открытии добавляется вручную.
7. **Карточки игроков и карты — снова видны всей сети**, блэклист общий на все казино. Страница Blacklist возвращается к прямому чтению таблицы игроков, временный ограниченный запрос удаляется.

## Как это отразится в панели Security

Пункты 1, 2, 3, 5, 7 после отката снова появятся в сканере как находки «данные видны всем». Они помечаются как намеренные (intentional) и заносятся в память безопасности с обоснованием: единая сеть из 4 казино, все пользователи — внутренний персонал, созданный администратором, публичной регистрации нет, общий блэклист обязателен для распознавания забаненного игрока в любом филиале. Это снимает их с роли блокировщиков публикации.

Останутся активными два предупреждения, не связанные с этим откатом: выключенная защита от утёкших паролей и общее чтение `casino_settings`.

## Технические детали

Одна миграция:

- `casino_visits`, `player_day_drop_cache`, `table_day_drop_cache`, `player_tags`, `player_daily_zones`, `management_rota`, `management_slots`, `management_attendance` — SELECT-политики возвращаются к `USING (true)` для роли `authenticated`.
- `players` и `player_cards` — SELECT-политики возвращаются к `USING (true)` для `authenticated`.
- `casino_license` — без изменений (остаётся `has_casino_scope`).
- `has_casino_scope(_uid, _casino_id)` — возвращается ранний выход `true` для ролей `manager`, `shift_manager`, `finance_manager`, `general_manager`, `boss`, `surveillance`, `super_admin` (через `user_roles`), плюс существующие проверки `profiles.casino_id` и `user_casino_access`.
- `DROP FUNCTION public.blacklist_network_players()`.

Отдельным data-запросом (не миграцией): вставка недостающих строк `user_casino_access` на все 4 казино для пользователей с ролями из списка выше (`ON CONFLICT DO NOTHING`).

Код: `src/pages/Blacklist.tsx` — возврат к постраничному чтению `players` с фильтром `status = 'blacklist'` (импорт `fetchPaged` восстанавливается).

Память безопасности обновляется: перечисленные находки фиксируются как намеренные архитектурные решения, а пункт про ограничение PII по казино убирается, чтобы будущие проверки не «чинили» это повторно.

Версия приложения поднимается до 1.3.652.
