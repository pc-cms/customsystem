# Super Admin: расходы по филиалам (просмотр + жёсткое удаление)

## Что подтверждено проверкой

- Данные есть: в `expenses` за 28/08–02/09 строки во всех филиалах (Arusha, Mwanza, Dodoma, Mbeya).
- Права в базе есть: super_admin видит все расходы, а удаление разрешено ролям super_admin / finance_manager в рамках филиала. Отдельная миграция не нужна.
- Права модулей есть: для super_admin модули «Expenses» и «Expenses Approvals» открыты на просмотр и запись с горизонтом «все дни».
- Активный филиал определяется поддоменом и работает одинаково для super_admin.
- Найден дефект в интерфейсе: на странице Expenses «менеджерский режим» включается только для ролей manager / shift_manager. Super Admin, Finance Manager и General Manager в него не попадают, поэтому у них скрыты колонка Source, возможность вносить задним числом и кнопки строк (Approve / Cancel / Edit).

Причина пустого списка пока не подтверждена: наиболее вероятно, что сохранённые в сессии фильтры (дата/источник/статус) отсекают строки. Это проверяется первым шагом.

## Шаги

1. Диагностика пустого списка
   - Открыть `/expenses` и `/expenses/approvals` под super_admin на конкретном поддомене филиала, посмотреть сетевой ответ запроса расходов и текущие значения фильтров.
   - Если строки приходят, а список пуст — виноваты сохранённые фильтры; чинится сбросом устаревших значений фильтров при загрузке страницы для управленческих ролей (дата → текущий бизнес-день, источник → All, статус → All).
   - Если строки не приходят — фиксируем точную ошибку/пустой ответ и правим запрос по факту, без догадок.

2. Управленческий режим для админских ролей
   - Включить «менеджерский режим» страницы Expenses для super_admin, finance_manager, general_manager наравне с manager / shift_manager: колонка Source, выбор источника в новых строках, внесение задним числом.
   - Показать действия строк (Approve / Cancel / Edit) этим ролям.
   - Страница Expenses Approvals: убедиться, что действия доступны тем же ролям.

3. Жёсткое удаление строки
   - Для super_admin добавить действие «Delete» с подтверждением, которое удаляет строку расхода физически (в отличие от нынешнего «отмена только неподтверждённых»).
   - Если у строки был проведён кошельковый расход, при удалении обратное движение по кошельку выполняется в той же операции, чтобы балансы не разъехались. Точный порядок уточняется по факту связей строки.
   - Остальным ролям поведение не меняется.

4. Проверка
   - Typecheck, тесты, сборка.
   - Проверка под super_admin на поддомене филиала: список виден, фильтры работают, удаление удаляет строку и не ломает баланс кошелька.
   - Поднять версию релиза после успешной сборки. Деплой не выполняется.

## Технические детали

- Затрагиваемые файлы: `src/pages/Expenses.tsx` (роль-гейт, фильтры, действия строк), `src/pages/ExpensesApprovals.tsx` (действия), `src/hooks/use-expenses.ts` (новая мутация hard delete), `package.json` (версия).
- База данных: изменений схемы не планируется; используются существующие политики удаления. Миграция потребуется только если удаление упрётся во внешние ключи — тогда это отдельный согласованный шаг.
- Финансовые формулы, расчёты Monthly Report и Wallets не меняются.
