# Company → Daily Balance: единая модель «всё есть Wallets»

## Идея

Отчёт — это Wallets и Office в удобном формате: сколько денег пришло (результат) и где они лежат (Cage Casino / Cage Office / Bank). Каждая колонка-деньги раскрывается в drill-down и показывает те же кошельки, что и страница Wallets — одни и те же цифры, один источник.

Ручная работа остаётся одна: после закрытия бизнес-дня менеджер вносит расходы и проверяет кошельки, жмёт **Record** — строка дня подтверждается и Balance сходится в ноль.

## Формула строки (один день)

```text
Money вчера + Result ± Diff + IN − Expenses − Transfer − OUT − Money сегодня = 0

Money сегодня = Cage Casino + Cage Office + Bank
Cage Casino   = вчерашний Cage + закрытия дня (Live Game + Slots по номиналам) − трансферы в офис/банк
Cage Office   = кошельки с флагом Office (сейфы валют + mobile money) на конец дня
Bank          = кошельки kind=bank (CRDB TZS/USD, NBC TZS/USD)
Result        = Столы + Слоты + Бар + JP
Diff          = chip difference + card balance дня
Transfer      = парные движения кошельков: офис → казино
Expenses      = офисные расходы дня
OUT / IN      = collections (см. ниже): OUT — обычная запись, IN — та же запись с минусом
```

## OUT и IN — это одна сущность: collections

- **OUT** — collections как сейчас: расход через office, деньги ушли из компании (владелец / AK).
- **IN** — та же категория collections, но с обратным знаком: деньги вернулись, значит денег стало больше. Отдельного механизма нет, отдельная строка «IN по казино» из collections казино тоже убирается.
- В таблице показываем одну колонку: положительное значение — красным как OUT, отрицательное — зелёным как IN. В формуле участвует один член со своим знаком.


## Унифицированный drill-down

Любая денежная ячейка раскрывается в один и тот же формат — список кошельков как в Wallets:

- **Cage Casino** — Safe Live, Safe Slots + разбивка по номиналам из закрытия дня (Live Game и Slots отдельными блоками), строка «вчерашний остаток» и строка «трансферы».
- **Cage Office** — все кошельки с флагом Office: Safe TZS / USD / EUR / GBP / KES (в валюте и в TZS по курсу дня) и мобильные (M PESA, Tigo, AirTell, Halo, Main Phone).
- **Bank** — CRDB TZS, CRDB USD, NBC TZS, NBC USD; в отчёте они идут как отдельные кошельки офиса, отдельная колонка Bank = их сумма.
- **Result / Diff / Expenses / Transfer / OUT-IN** — расшифровка по источникам: по казино, по категориям, по парам переводов, по записям collections (со знаком).

Компонент drill-down один на все колонки: заголовок, строки «кошелёк — валюта — сумма — сумма в TZS», итог.

## Флаг Office на кошельке

В настройках кошельков добавляется переключатель **Office wallet**. Отмеченные кошельки формируют Cage Office; неотмеченные кассовые (Safe Live / Safe Slots) идут в Cage Casino. Это убирает текущую догадку по типам и делает разбиение управляемым.

## Стартовый баланс и переход между месяцами

- Вы вносите цифры в строку **Start** (Cage Casino, Cage Office, Bank). Значения хранятся в базе, не в браузере.
- Дата старта не фиксируется заранее: первым рабочим днём становится тот день, в который вы впервые нажали **Record**. Нажали сегодня — счёт идёт с сегодня, нажали завтра — с завтра. До этого таблица показывает только строку Start.
- Строка Start заполняется вручную ровно один раз — при запуске. Дальше она пересчитывается сама.
- **Переход месяца:** Start нового месяца = Money последнего дня предыдущего месяца (30/31), автоматически, вручную ничего не вводится. Таблица непрерывная: месяцы — это только окно просмотра одного и того же журнала.
- Строка Start отображается первой в месяце, только для чтения (кроме самого первого месяца запуска), с подсказкой «carried over from 31/07».


## Статус строки: Pending → Recorded

1. Бизнес-день закрыт → строка появляется сразу, помечена **Pending**. Cage Office и Bank показываются по последнему снимку, Balance подсвечен как непроверенный.
2. Менеджер вносит расходы, сверяет кошельки, жмёт **Record** в Wallets.
3. Снимок офиса и банка фиксируется на этот день, строка становится **Recorded**, Balance пересчитывается сразу, без перезагрузки.
4. Balance ≠ 0 → какое-то движение не внесено; клик открывает расшифровку всех компонентов дня.

## Что чиним по пути

- Cage Office сейчас берётся из ручного поля «Start» в браузере — заменяем на кошельки с флагом Office.
- Колонки «IN по казино» из collections убираем — остаётся одна колонка OUT/IN по знаку записи collections.
- Transfer определяется догадкой («любой приход, кроме банка») — заменяем на вторую ногу парного перевода офис → казино.

- Result считает только столы и слоты — добавляем бар и JP, Diff выносим отдельно.
- Cage Casino должен читать закрытия по номиналам в одном формате для Live и Slots — проверяем запись при закрытии смены.

## Технические детали

- Миграция: `fin_wallets.is_office boolean not null default false`; таблица стартовых значений отчёта (cage_casino, cage_office, bank, дата первого Record проставляется автоматически); проставить флаг существующим `cash` и `mobile_money`. Отказ от `localStorage` в `StartingBalanceTile` для этого отчёта.
- `use-day-balance-snapshot.ts`: снимок пишется по `is_office` и `kind='bank'`, добавляется признак подтверждения дня; после успеха `invalidateFinance(qc)`.
- `use-office-balance-report.ts`: старт из базы; Cage Casino как running-баланс (вчера + закрытия − трансферы); Cage Office/Bank из снимка; Transfer по парам `transfer_out`/`transfer_in`; одно поле `collections_net` (сумма collections со знаком: плюс = OUT, минус = IN); полный Fin Result; поле `status: pending | recorded`; на каждую ячейку возвращать массив строк для drill-down.
- Новый общий компонент `WalletDrillPanel` (список кошельков + номиналы + итог), используется всеми колонками отчёта.
- `OfficeBalanceReport.tsx`: бейдж Pending/Recorded, строка Start первой в месяце (редактируемая только до первого Record, дальше carry-over из последнего дня прошлого месяца), единый drill на всех денежных колонках.
- Настройки кошельков: переключатель Office wallet (finance_manager и выше).
- Демо-данные `src/lib/demo-report-data.ts` привести к новой структуре. Поднять версию в `package.json`.

## Порядок запуска

1. Флаг Office + стартовые значения в базе + Record пишет снимок офиса и банка, статус строки.
2. Cage Casino как running-баланс из закрытий, Transfer по парам, OUT/IN одной колонкой из collections, полный Result и Diff.
3. Единый drill-down на всех колонках.
4. Ваш проход: задать дату старта и суммы, отметить офисные кошельки, за первый день нажать Record и убедиться, что Balance = 0.
