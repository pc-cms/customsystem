# Company Report грузится минутами — диагностика и ускорение

Отчёт Dashboard TV висит на «Loading monthly report…». Причина пока не подтверждена: данных мало (расходы за август — 514 строк, `fin_day_closing` — 148, закрытий дня — 417), все нужные индексы на месте, значит объём данных сам по себе не может давать 5 минут. Поэтому сначала измеряем, потом чиним — без догадок.

## Шаг 1. Измерить, где именно теряется время

- Замерить реальное время вызова `boss_monthly_report` из браузера под живой сессией (вкладка Network: время ответа, статус, число повторов).
- Проверить, не уходит ли запрос в таймаут и не повторяется ли он автоматически (у запроса стоит авторефетч раз в 60 секунд плюс встроенные ретраи — при неудаче это выглядит как «грузится 5 минут»).
- Замерить ту же функцию напрямую в базе под ролью обычного пользователя (с включёнными политиками доступа) и сравнить с замером без политик.

Результат шага: точный ответ — тормозит SQL, тормозят политики доступа, или запрос падает и молча повторяется.

## Шаг 2. Убрать известные слабые места функции

Независимо от результата замера, в текущей функции есть места, которые стоит починить:

- Курс валюты (`boss_fx_rate`) вызывается отдельно для каждой строки расходов и бюджета. Заменяем на один предрасчёт курсов (казино + валюта + дата) в отдельном CTE и джойн — вместо вызова функции построчно.
- Подсчёты по казино сейчас идут отдельными подзапросами на каждое казино (6 подзапросов × число казино). Переписываем на групповые агрегаты с `GROUP BY casino_id`.
- Функция и `boss_fx_rate` работают как `SECURITY INVOKER`, поэтому политики доступа применяются к каждой вложенной выборке, включая таблицы курсов. Переводим обе в `SECURITY DEFINER` с явной проверкой прав в начале: пользователь получает данные только по тем казино, к которым у него есть доступ (проверка через существующие функции ролей/скоупа), остальные ID отбрасываются.

## Шаг 3. Поведение интерфейса при долгом ответе

- Ограничить время ожидания и число повторов, чтобы страница не висела бесконечно: при ошибке сразу показывать сообщение и кнопку Retry (сейчас блок ошибки уже есть — подключаем его к таймауту).
- Автообновление раз в 60 секунд не должно запускаться, пока предыдущий запрос ещё не завершился.
- Пока данные грузятся впервые, показывать скелет таблицы вместо строки текста.

## Технические детали

- Изменения в SQL: новая версия `public.boss_monthly_report(uuid[], int, int)` и `public.boss_fx_rate(...)` — `SECURITY DEFINER`, `STABLE`, `SET search_path = public`, с фильтрацией `_casino_ids` по доступу вызывающего.
- Индексы добавлять не требуется: `idx_expenses_casino_bd`, `fb_casino_period`, `foi_casino_bd`, `idx_bdc_casino_date`, `fin_daily_rates_casino_date_idx` уже покрывают все выборки.
- Клиент: `src/hooks/use-boss-monthly-report.ts` (retry/timeout, `refetchInterval` без наложения) и `src/components/.../monthly-report-panel.tsx` (скелет вместо текста). Формулы и состав строк отчёта не меняются.
- Версия приложения повышается.

## Что не меняется

Состав отчёта, формула Balance, бонус 5%, правила «только закрытые дни», права доступа к отчёту.
