# Users & Roles: доступы к казино, удаление, матрица расхождений

## 1. Управление доступом к казино прямо в матрице пользователей

В таблице Users колонка Casino сейчас только показывает основное казино и «+N». Делаю её редактируемой, а также добавляю переключатель «Show inactive / Hide inactive»:

- Клик по ячейке Casino открывает поповер со списком всех казино и чекбоксами.
- Отметил — доступ выдан, снял — доступ убран (строка в списке доступов удаляется).
- Основное казино профиля помечено значком «Primary», его нельзя снять — только сменить (выбор Primary в том же поповере).
- Ячейка показывает: Primary + чипы дополнительных казино.
- Права на изменение: только Super Admin; Manager видит без возможности править.
- В тулбаре таблицы добавляется переключатель «Show inactive» / «Hide inactive». По умолчанию неактивные скрыты. Отключённые пользователи (disabled) вместо исчезания просто сереют и пропадают при выключенном тогле.

## 2. Полное удаление пользователя

Сейчас корзина только «отключает» — строка становится серой. Меняю на две кнопки:

- **Disable** — как сейчас: вход закрыт, запись остаётся серой (обратимо, добавлю кнопку Enable).
- **Delete** — полное удаление: логин, профиль, роли, персональные права и доступы к казино удаляются, строка исчезает из таблицы. Подтверждение вводом логина.

Исторические записи (логи, транзакции, смены) остаются — в них имя показывается как «Deleted user», ничего не ломается.

## 3. Матрица расхождений по ролям

Новая вкладка «Consistency» в Users & Roles.

Для каждой роли сравниваю фактические права каждого пользователя с базовыми настройками роли и показываю таблицу: модуль × пользователи роли, где отличия подсвечены.

Что уже видно в базе сейчас (по фактическим персональным переопределениям):

| Роль | Пользователей | С личными отклонениями |
|---|---|---|
| Manager | 8 | 2 (Michael — снято ~25 модулей; GM — снят ряд модулей) |
| Shift Manager | 4 | 1 |
| HR | 2 | 1 |
| Cashier Slots | 3 | 1 |
| Pit | 5 | 0 |
| Reception | 5 | 0 |
| Cashier | 3 | 0 |
| Surveillance | 4 | 0 |

То есть Pit, Reception, Cashier, Surveillance между собой одинаковы; расхождения только у Manager, Shift Manager, HR и Cashier Slots — и все они созданы вручную через персональные права.

Действия на вкладке:
- Фильтр по роли и переключатель «показывать только отличия».
- Кнопка **Align to role defaults** для выбранных пользователей — удаляет их персональные переопределения, пользователь возвращается к базовым настройкам роли.
- Кнопка на строке модуля — выровнять всех по этому модулю.

## Технические детали

- `UsersTab.tsx`: редактируемая ячейка Casino (insert/delete в `user_casino_access`, смена `profiles.casino_id`), вторая кнопка действия Delete, кнопка Enable для отключённых.
- Новая edge-функция `delete-user`: проверка роли вызывающего (Super Admin; Manager — только своё казино и не Super Admin), удаление из `user_roles`, `user_module_permissions`, `user_casino_access`, `profiles`, затем `auth.admin.deleteUser`.
- Edge-функция `disable-user` дополняется режимом снятия блокировки (`enable`).
- Новый компонент `ConsistencyTab.tsx` + хук: читает `role_module_defaults`, `user_module_permissions`, `user_roles`, строит матрицу; выравнивание = delete строк `user_module_permissions`.
- `CasinoAccessManagement.tsx` и его вкладка удаляются.
- Проверка после изменений: удаление тестового пользователя, снятие доступа к казино, выравнивание одной роли; прогон `src/test/access-matrix.test.ts`.
