# Единый бизнес-день 07:00 — все казино (визиты, автовыходы, хардкод 05:00)

## Во сколько сейчас автовыходы (проверено в базе)

- `auto_close_business_day` — cron в **02:00 UTC = 05:00 EAT**. Закрывает **все** открытые визиты и клиентские сессии без всякой проверки часа. Последний запуск: 03/08 02:00 UTC. Это и есть «автовыход в 5 утра» — он бьёт по смене, которая работает до 06:00, во всех казино сразу.
- `close_open_sessions_5am` — cron в **05:05 UTC = 08:05 EAT**, внутри уже стоит правильная защита `hour >= 7`. Здесь всё корректно (имя функции просто устарело).
- `auto_close_forgotten_business_days` — 17:05 UTC = 20:05 EAT, закрывает вчерашний бизнес-день, если его забыли. Защита `hour >= 11`. Корректно.

## Найденный хардкод «05:00» помимо этого

1. Триггеры визитов `ensure_visit_on_transaction` и `ensure_visit_on_chip_transfer` — считают бизнес-дату по `hour < 5`, а не через `business_date_of` (07:00). Отсюда ошибка `uniq_casino_visits_open_per_player` в окне 05:00–07:00.
2. Расчёт бизнес-даты смены по `opened_at` с `hour < 5` в `compute_shift_table_results`, `populate_table_daily_results_for_day`, `trg_recalc_shift_tables_on_snapshot`.
3. Комментарии/подписи во фронтенде, где всё ещё написано «05:00 rollover» (`use-visits.ts`, `use-cash-checks-by-date.ts`, `MissChips.tsx`) — фактическая логика уже 07:00, вводит в заблуждение.
4. `slots-tips-bucket.ts` — вечерний бакет чаевых слотов «21:11–05:00». Это отдельная бизнес-настройка кассы, не ролловер; трогаем только если подтвердите.

## Что сделать

1. Перенести/защитить автовыход: `auto_close_business_day` не должен работать раньше ролловера. Добавить внутрь проверку часа EAT (`< 7 → выход`) и перевести расписание cron на **04:05 UTC (07:05 EAT)**. Так ни одно казино не теряет игроков в 05:00–06:00.
2. Привести триггеры визитов к `public.business_date_of(now())` и сделать вставку устойчивой: если у игрока висит открытый визит другого дня/казино — сначала закрыть его, потом открыть визит текущего бизнес-дня.
3. Привести бизнес-дату смены к `business_date_of` в трёх функциях расчёта результатов столов.
4. Разово закрыть зависшие открытые визиты прошлых бизнес-дней по всем казино.
5. Обновить устаревшие комментарии «05:00» во фронтенде на 07:00 (без изменения логики).

## Технические детали

- Одна миграция: `CREATE OR REPLACE` для пяти функций + `cron.alter_job`/пересоздание расписания `auto_close_business_day`.
- Индекс `uniq_casino_visits_open_per_player` не трогаем — логику подгоняем под него.
- Нормализация данных отдельным апдейтом: `checked_out_at IS NULL AND date < business_date_of(now())`.
- Проверка после применения: `cron.job` показывает новое время, открытых визитов прошлых дат нет, пересчёт результатов смены не сдвигает бизнес-даты.
