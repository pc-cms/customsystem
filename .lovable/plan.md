# Уведомление об обновлении + доступ Shift Manager к Staff Master

## 1. Обновление: убрать полноэкранный попап

Сейчас при новой версии открывается затемнённое окно на весь экран, которое нельзя закрыть — работа с формой прерывается.

Новое поведение:
- Полноэкранное окно убирается полностью. Всегда показывается компактная карточка внизу справа (как сейчас в режиме «есть несохранённые данные»).
- В карточке: заголовок "New version available", текущая версия, кнопка "Update now" и крестик "Dismiss".
- После закрытия крестиком напоминание возвращается через 30 минут; при появлении ещё более новой версии — сразу.
- Карточка не перехватывает клики по странице, не блокирует ввод; при несохранённых данных текст остаётся предупреждающим ("Finish and save your current entry, then update").
- Состояние «отложено» хранится в sessionStorage (на вкладку), так что перезагрузка/новый вход показывает напоминание снова.

## 2. Staff Master для Shift Manager

Валерий (Мванза) — роль Shift Manager. Сейчас Staff Master скрыт и запись в справочник сотрудников разрешена только HR / Manager / Super Admin.

Изменения (для всех Shift Manager, не только для Валерия):
- В матрицу ролей добавляется модуль Staff Master для роли Shift Manager: просмотр + запись, горизонт "all".
- Пункт меню "Staff Master" в сайдбаре становится видимым для Shift Manager.
- Правила доступа к таблице сотрудников расширяются так, чтобы Shift Manager мог добавлять, изменять и удалять сотрудников только своего казино. Остальные роли не меняются.
- Больше ничего Shift Manager не получает — прочие права остаются как были.

## Технические детали

Файлы:
- `src/components/PWAUpdateNotification.tsx` — удалить ветку полноэкранного оверлея, оставить единственный вариант — угловая карточка с кнопкой закрытия; добавить snooze (30 мин) с ключом по версии в sessionStorage.
- `src/components/layout/AppSidebar.tsx:104` — добавить `shift_manager` в `roles` для `/staff/master`.

База:
- `INSERT` в `role_module_defaults` строки `('shift_manager','staff_master', true, true, 'all')` (run_sql, upsert по конфликту).
- Миграция: политика `employees_write_hr` дополняется условием `has_role(auth.uid(),'shift_manager') AND has_casino_scope(auth.uid(), casino_id)`; политика `employees_select_payroll_roles` не требует изменений (Shift Manager уже видит сотрудников своего казино через `employees_select_same_casino`).
- Проверить, что удаление сотрудника (`employees.delete`) проходит существующие триггеры очистки связей — они не зависят от роли.
