# Закрытие смены Аруши 10/08 и принудительное автозакрытие в 08:00

## Часть 1. Закрыть смену Аруши за 10/08 (по данным из печатного отчёта)

Открытая смена столов Аруши (открыта 10.08 17:41 EAT) закрывается со следующими данными:

- Пересчёт кассы на закрытие: 240 000 TZS и 3 750 USD.
- Miss Chips (недостача по номиналам): 50k x1, 10k x8, 5k x1, 2k x1, 1k x1 — итого −138 000 TZS.
- Результат столов: 372 000 (уже зафиксирован по столам).
- Цифры Close Day (Drop Slots / Net Win / CashDesk / Client Balance) уже внесены — не трогаем.
- Статус смены -> closed, время закрытия 06:00 EAT 11.08, в заметках пометка о закрытии по печатному отчёту.
- Пересчитываются производные: cash result, miss total, shift result, balance.

После этого дозаполнять ничего не потребуется.

## Часть 2. Принудительное автозакрытие в 08:00 EAT

Новая процедура `force_close_business_day_0800`, по расписанию ежедневно в 08:00 EAT (05:00 UTC), для каждого казино, где за вчерашний бизнес-день нет ручного Close Day:

1. Закрыть открытые смены Cage Slots за этот бизнес-день (расчётные значения, пометка forced).
2. Закрыть открытую смену столов казино (результаты столов фиксируются как есть; поля пересчёта кассы остаются пустыми и доступными менеджеру).
3. Закрыть активные сессии игроков и открытые визиты.
4. Создать запись закрытия бизнес-дня (`close_business_day` с force), если её ещё нет; в `fin_day_closing` Drop Slots / Net Win / CashDesk / Client Balance пишутся нулями и остаются доступными для ручного ввода.
5. Записать результат прогона в `cron_run_log` (что закрыто, что упало с ошибкой).

Существующее автозакрытие в 11:00 остаётся страховочной второй попыткой — оно ничего не делает, если день уже закрыт в 08:00.

## Технические детали

- Миграция: функция `public.force_close_business_day_0800()` (SECURITY DEFINER), переиспользует `compute_shift_close`, логику закрытия cage-смены и `close_business_day(_casino_id, 'auto_0800', true)`.
- Расписание `pg_cron` на 05:00 UTC добавляется отдельно как данные (не миграция).
- Разовое закрытие смены Аруши 10/08 с указанными цифрами выполняется как data-операция.
- Версия в `package.json` поднимается до 1.3.586.
