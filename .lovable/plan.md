# Безопасность: журнал замечаний и точечные исправления 6, 10, 11

## Новое правило проекта
- Все замечания проверок, критичные и некритичные, сначала записываются в журнал. Без решения Ивана ничего не исправляется и не скрывается.
- Правило сохраняется в память проекта. Журнал хранится в файле `.lovable/security-journal.md`: номер, суть, уровень, решение, статус.
- В журнал вносятся все 33 замечания глубокой проверки с вашими решениями: 1, 2, 3, 5, 8 — «не трогаем», 4, 7, 9 — «ждут ответа», 6, 10, 11 — «исправить». Остальные 22 записываются со статусом «на рассмотрении».

## Ответы на ваши вопросы
**4. Служебные проверки копирования данных.** Это ночная задача в 04:00, которая сверяет количество строк в облаке с копиями серверов казино. Её может запустить кто угодно по ссылке, без пароля. Данные она не меняет и не показывает, но лишний запуск нагружает базу. Можно разрешить запуск только по расписанию с секретным ключом.

**7. Синхронизация.** Функция приёма изменений с локальных серверов казино. Через неё вошедший сотрудник любой роли может записать или изменить строку почти в любой таблице: транзакции, игроков, смены, фишки, роли. Это может сделать и кассир, если знает, как вызвать функцию напрямую, минуя экраны. Можно разрешить её только серверам синхронизации, но сначала нужно проверить, кто её вызывает. Иначе синхронизация может сломаться.

**9. Журнал действий.** Функция очистки старых записей журнала доступна любому вошедшему: один вызов стирает журнал за выбранное число дней. Можно оставить её только Super Admin или автоматической задаче.

## Что исправляем
**6. Токены клуба.** Если основной ключ подписи не найден, сейчас используется запасной, вплоть до известного «dev-secret». Запасной вариант убираем: без ключа вход в клуб не выдаёт токен. Действующие токены продолжат работать, потому что основной ключ уже задан.

**10. Создание пользователей.** Manager сможет выдавать только свою роль или роли ниже. Super Admin и роли выше Manager будет выдавать только Super Admin. Порядок ролей перед изменением сверю с вами по текущему списку.

**11. Расчётный лист.** Имя, должность и другие тексты в печати будут выводиться как обычный текст, без выполнения кода. Внешний вид и суммы не меняются.

## Технические детали
- 6: `supabase/functions/_shared/club-token.ts` — только `SUPABASE_JWT_SECRET`, при его отсутствии ошибка 500.
- 10: `supabase/functions/create-user/index.ts` — проверка иерархии ролей вызывающего перед вставкой в `user_roles`.
- 11: `src/lib/payroll-exports.ts` — функция escapeHtml для всех строковых полей в HTML расчётного листа.
- Без migrations и без изменений данных. После правок 6, 10, 11 помечаются как исправленные, остальные остаются активными.
