# Единый бизнес-день 07:00 для визитов — все казино

## Что происходит

Кассир (на фото — Mwanza, 05:07) проводит IN: часть транзакций проходит, часть падает с
`duplicate key value violates unique constraint "uniq_casino_visits_open_per_player"`.

Причина подтверждена чтением функций в базе:

- Индекс `uniq_casino_visits_open_per_player` разрешает игроку ровно один открытый визит (`checked_out_at IS NULL`) во всей системе (глобально, не по казино).
- `business_date_of()` = ролловер 07:00, `get_current_business_date()` = 07:00, автозакрытие `close_open_sessions_5am` тоже работает только с 07:00.
- Но триггеры `ensure_visit_on_transaction` и `ensure_visit_on_chip_transfer` до сих пор считают дату по старому правилу «час < 5 → вчера», то есть ролловер 05:00.

Итог (одинаково для всех казино — триггеры общие): в окне 05:00–07:00 EAT триггер считает бизнес-день уже следующим, не находит визита с этой датой и вставляет новый открытый визит, хотя у игрока ещё открыт визит за прошлый день. Индекс блокирует вставку — вся транзакция откатывается. Именно это окно на фото.

## Что сделать

1. Привести триггеры визитов к единому бизнес-дню `public.business_date_of(now())` (07:00):
   - `ensure_visit_on_transaction`
   - `ensure_visit_on_chip_transfer`
2. Сделать вставку визита устойчивой к индексу: если у игрока есть открытый визит с другой датой или в другом казино — сначала закрыть его (`checked_out_at = now()`), затем открыть визит текущего бизнес-дня. Для текущего бизнес-дня сохраняется поведение «переоткрыть закрытый визит».
3. Нюансы из-за работы до 06:00 — привести к `business_date_of` расчёт бизнес-даты смены (там осталось старое `hour < 5` от `opened_at`) в:
   - `compute_shift_table_results`
   - `populate_table_daily_results_for_day`
   - `trg_recalc_shift_tables_on_snapshot`
   Это влияет на смены, открытые/пересчитанные после полуночи: сейчас смена, тронутая между 05:00 и 07:00, может быть отнесена к следующему дню и «уехать» из отчётов закрытия.
4. Одноразовая нормализация данных: закрыть зависшие открытые визиты прошлых бизнес-дней (сейчас в Mwanza их 2 за 02/08), чтобы кассиры не ловили ошибку прямо сейчас.

Изменения только в базе; фронтенд трогать не нужно.

## Технические детали

- Одна миграция: перезапись тел пяти функций (`CREATE OR REPLACE`), таблицы и индексы не меняются.
- Индекс `uniq_casino_visits_open_per_player` сохраняем — он остаётся защитой от дублей, логику приводим в соответствие с ним.
- Закрытие зависших визитов — отдельным data-обновлением по условию `checked_out_at IS NULL AND date < business_date_of(now())`.
- Проверка после применения: список открытых визитов по всем казино, пробный пересчёт результатов смены и контроль, что бизнес-даты не сместились.
