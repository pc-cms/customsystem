# Печать отчётов после закрытия смены — починить

## Что происходит сейчас

- **Live Game (касса).** После подтверждения менеджером смена перестаёт быть активной. Страница «Close Shift» в этот момент показывает состояние «Loading…» и полностью скрывает всё содержимое, включая уже открытое окно печати. Пользователь видит только переход к открытию новой смены.
- **Slots.** После подтверждения происходит переход на отдельную страницу печати. Если эта страница не успевает получить сохранённый отчёт (или переход перебивается обновлением данных о смене), окно печати не показывается, и человек оказывается на экране открытия новой смены.

Итог: обязательное окно печати не появляется ни в живой игре, ни в слотах.

## Что делаем

1. **Live Game:** после подтверждения менеджера сразу открывается отдельная страница печати «Print Shift Closing Pack» (как в слотах), а не окно поверх исчезающей страницы закрытия. Так окно печати не может пропасть вместе со сменой.
2. **Slots:** страница печати всегда показывает окно, даже пока отчёт подгружается (внутри — «Loading…», кнопки становятся активны, когда данные готовы). Никаких молчаливых уходов на открытие смены.
3. **Страховка на случай сбоя:** идентификатор только что закрытой смены запоминается локально. Если человек всё же оказался на экране кассы или слотов без печати, окно печати открывается там автоматически один раз. После печати или закрытия окна отметка снимается.
4. **Кнопка Print на экранах Manager Review** (Live и Slots) — проверяем и оставляем на видном месте, чтобы можно было напечатать вручную в любой момент.
5. Содержание листов, расчёты и правило «печатается зафиксированный снимок» не меняем.

## Проверка

- Закрыть тестовую Live-смену: окно печати появляется, закрывается только кнопкой Print или Close without printing, затем переход в Cage.
- Закрыть тестовую Slots-смену: то же самое.
- Кнопки Print в Manager Review открывают тот же пакет.
- Повторная печать из Reports/Statistics работает без изменений.
- Поднять версию приложения. Публикация — только по отдельной команде.

## Технические детали

- Новый маршрут `/cage/print/:shiftId` (страница по образцу `src/pages/cage-slots/PrintSlotsShiftPage.tsx`) рендерит `ReprintShiftDialog mandatory`. `CloseShiftPage` в `onSuccess` закрытия делает `navigate` на него вместо локального `printShiftId`; ранний `return` при `!shift` больше не может «съесть» диалог.
- `PrintSlotsShiftPage`/`PrintSlotsShiftDialog`: диалог монтируется сразу, состояние загрузки снимка отображается внутри, кнопка Print блокируется до готовности (`packReady`).
- Страховка: запись `pendingPrint = { kind: "live" | "slots", shiftId }` в `localStorage`, чтение на `/cage` и `/cage-slots`, авто-открытие соответствующего mandatory-диалога и очистка ключа в `onClose`.
- Кнопка Print в Manager Review: `ReprintShiftDialog` (Live, шаг manager review в `CloseShiftDialog`) и `PrintSlotsShiftDialog` (Slots, `ActiveSlotsShiftView`) в немодальном режиме.
