# Упрощение логики Balance / Variance

## Цель

Одна простая формула, без «памяти кошельков», привязок к транзакциям и скрытых условий:

```text
Expected = Starting Float + Incomes − Expenses − Collections
Actual   = физически посчитанные деньги (все кошельки)
Variance = Actual − Expected
```

Incomes берутся только из Day Closing (Live + Slots + Other Incomes + Card Balance + Miss Chips/Cards) — так, как их вручную вносят каждое утро.
Expenses учитываются после закрытия бизнес-дня (для office — сразу, как и сейчас).

## Что убираем из расчёта

1. Условие «расход считается только если по нему есть проведённая транзакция кошелька» (`EXISTS fin_wallet_tx ... posted_at`). Сейчас по Мванзе за август 29 кассовых расходов на 2 450 500 TZS вообще не попадают в Expected именно из-за этого условия — это и есть источник «плавающего» Variance.
2. Разделение логики на «office сразу / cage через транзакцию». Остаётся одно правило: день закрыт → расход в Expected.
3. Лишние ветки округления и дублирующие подсчёты Collections/Transfers сводим к одному проходу по таблице расходов.

Списание денег с кошелька остаётся как есть — это просто удобство: оно уменьшает Actual. Если расход внесён, а деньги ещё не сняты с кошелька, Variance покажет разницу; нажали «убрать деньги» — Variance вернулся к 0.

## Что добавляем

**Панель расшифровки Variance** (раскрывающийся блок в Balance): построчно показывает каждый компонент формулы и по дням — Incomes, Expenses, Collections, изменение Actual — чтобы любую разницу можно было увидеть глазами, а не гадать.

**Аудит по дням**: таблица день × (Income из Day Closing, Расходы, Инкассации, Δ Actual, дневной Variance). Так сразу видно, в какой день расхождение появилось.

## Отдельный вопрос: деньги в кассе

Выручка попадает в систему через Day Closing утром, а физически деньги ещё какое-то время лежат в кассе (Live/Slots) и не входят ни в один посчитанный кошелёк. Пока эти наличные не инкассированы в сейф, Actual будет ниже Expected на эту сумму — формально это будет выглядеть как недостача.

Чтобы этого не было, в расшифровке заведём строку **«Не инкассировано (касса)»** — вычисляемый остаток кассы (Income дня − инкассации по этому дню − кассовые расходы). Он показывается отдельной строкой и не считается недостачей.

## Проверка после изменений

Пересчитать Мванзу за август по-новому и сверить построчно: Starting Float, Incomes по трём закрытым дням (01–03/08), 44 расхода, инкассации, физические счёты кошельков. Результат разобрать по дням в новой панели и показать, из чего складывается итог.

## Технические детали

- Переписать RPC `fin_balance_snapshot`: убрать `EXISTS fin_wallet_tx` из трёх подзапросов по `expenses`, свести Collections/Transfers/Expenses в один агрегат с разбивкой, добавить в ответ массив `daily` (по дням) и блок `breakdown`.
- Actual по кошельку: последний физический счёт + проведённые транзакции после него; если счёта нет — ledger. Логика сохраняется, но выносится в один CTE без дублей.
- Frontend: `src/hooks/use-fin-balance.ts` — прокинуть `daily`/`breakdown`; в `FinancesWalletsPage.tsx` добавить сворачиваемую панель расшифровки.
- Поднять версию в `package.json`.
