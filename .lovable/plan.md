# Предупреждения безопасности: что это и что делать

Критических проблем нет. Есть 15 замечаний: 10 предупреждений и 5 информационных.

## Важные — рекомендую исправить
1. **Объединение игроков (merge_players) может запустить кто угодно, даже без входа.** Эта функция собирает команды базы из переданных данных и работает с полными правами. Исправление: запускать её могут только вошедшие пользователи с ролью Manager / Super Admin, сборку команд из входных данных убрать. Само объединение работает как раньше.
2. **Полная очистка данных казино (sync_wipe_casino_data) доступна любому вошедшему пользователю.** Это самая опасная функция: она стирает данные казино. Исправление: оставить только Super Admin или серверную синхронизацию и убрать сборку команд из входных данных.
3. **Не проверяются утёкшие пароли.** Сейчас при регистрации и смене пароля можно поставить пароль из публичных баз утечек. Исправление: включить проверку. Старые пароли продолжат работать.
4. **Фото игроков (player-photos): любой вошедший может загрузить файл куда угодно в хранилище.** Исправление: загружать фото могут только Reception / Manager / Super Admin своего казино.
5. **Ещё одно правило хранилища разрешает любому вошедшему загружать файлы.** Исправление: ограничить его по ролям, как в п. 4.

## Неважные — рекомендую принять (не исправлять)
Справочники, которые читают все вошедшие сотрудники. Секретных данных в них нет, а экранам эти таблицы нужны:
- shift_codes (коды смен), expense_categories, fin_categories, fin_main_categories (категории расходов);
- casino_settings (настройки казино), chip_color_settings (цвета фишек), casino_packages (пакеты);
- pos_modifier_menu_items, pos_modifier_recipe_effects (модификаторы меню POS);
- casino-branding: логотипы и так публичны, видно только их список.

Предлагаю пометить их как «принято»: доступ нужен по работе и не раскрывает чужих данных.

## Что не меняется
Цифры, отчёты, роли пользователей и интерфейс остаются как есть.

## Технические детали
- Миграция: `REVOKE EXECUTE ... FROM PUBLIC, anon` для merge_players и sync_wipe_casino_data; GRANT только authenticated + проверка `has_role` внутри; заменить динамический EXECUTE на `format()` с `%I` / `%L` или статический SQL (сначала прочитать тела функций и вызовы из UI и edge functions).
- Auth: включить password HIBP check.
- Storage: политики INSERT/UPDATE для player-photos и второго бакета с проверкой роли и `casino_id` в пути.
- Справочники и casino-branding пометить в сканере как ignore с объяснением.
