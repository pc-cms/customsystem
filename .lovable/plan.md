# Day Closing: убрать сверку Slots с кассовыми сменами

## Проблема

При блокировке Day Closing в Arusha за 25.08 выдаётся ошибка:
`Variance detected (tables Δ=0.00, slots Δ=-994784.00) — a reconciliation comment is required`

Причина подтверждена данными: функция блокировки сравнивает введённый Slots (9 384 236) с суммой результата закрытых кассовых слот-смен из снапшота закрытия дня (10 379 020). Это два независимых источника: Day Closing Slots — это ACE Net Win / ручной ввод, а слот-смена кассы — кассовый цикл. Разница возникает почти каждый день (в предыдущие дни её «закрывали» комментариями Fill 1M / 2M / 4M / 5M / 6M).

## Решение

Slots не сверяем вообще: ACE-коллектор либо ручной ввод — источник истины.

- Из проверки блокировки убрать slots-условие: обязательный комментарий остаётся только при расхождении по Tables.
- В панели Reconciliation на странице Day Closing строку Slots оставить как справочную: показывать значение смен и Δ нейтральным цветом, без красного и без требования комментария.
- Поле комментария и его валидация (минимум 3 символа) остаются, но включаются только по Tables.
- Заблокировать текущий день Arusha 25.08 станет возможно сразу после изменения — отдельная правка данных не нужна.

## Технические детали

- Новая миграция с `CREATE OR REPLACE FUNCTION public.fin_lock_day_closing(uuid, text)`: `v_needs_note := abs(v_diff_tables) > 1;` (slots-дельта по-прежнему считается и пишется в `fin_audit_log` для истории, но не блокирует). Остальное тело функции — проводка income lines, установка `locked_at`, аудит — без изменений.
- `src/pages/finances/FinancesDayClosingPage.tsx`: `needsVariance` считать только по `diffTables`; для строки Slots убрать класс `cms-amount-negative`, показать Δ как справочную; текст-подсказку «Matches Cage closure» скорректировать под Tables.
